# 1. Time-Series Forecasting Using GRU

A **Gated Recurrent Unit (GRU)** is another type of recurrent neural network designed for sequential data and time-series forecasting.

Like an LSTM, a GRU uses **gates** to control the flow of information through the network. However, the GRU has a simpler architecture and does not maintain a separate cell state.

Therefore, a GRU can provide a good balance between the ability to learn temporal dependencies and model complexity.

## 1.1 Basic Idea of a GRU

A GRU maintains a single type of state:

```text
Hidden State
     hₜ
```

Unlike an LSTM, a GRU does **not** have a separate cell state.

The hidden state carries information from previous time steps and is updated at each time step.

The important idea is:

> The GRU learns which information from the previous time step should be retained and how much new information should be incorporated into the current hidden state.

At each time step, the GRU receives:

* the current observation,
* the hidden state from the previous time step.

Therefore, information can be carried from earlier observations to later observations.

## 1.2 GRU Gates

The main difference between a basic RNN and a GRU is the use of **gates**.

A GRU contains two main gates:

1. **Update Gate**
2. **Reset Gate**

These gates control how information flows through the network.

### Update Gate

The **update gate** determines how much information from the previous hidden state should be retained and how much new information should be incorporated.

A larger update-gate value means that more information from the previous hidden state is retained.

Therefore, the update gate helps the GRU preserve useful information over time.

### Reset Gate

The **reset gate** determines how much of the previous hidden state should be used when calculating the new candidate information.

The reset gate allows the GRU to reduce the influence of previous information when it is no longer useful.

## 1.3 GRU Architecture

For our time-series forecasting problem, the overall architecture is:

```text
Input
(batch_size, window_size, 1)
            │
            ▼
           GRU
      hidden_size=128
            │
            ▼
       Last Time Step
            │
            ▼
        Linear Layer
         128 → 1
            │
            ▼
      Predicted Price
```

For our current configuration:

```text
Input
(64, 60, 1)
    │
    ▼
GRU
hidden_size = 128
    │
    ▼
Last Time Step
(64, 128)
    │
    ▼
Linear
128 → 1
    │
    ▼
Prediction
(64, 1)
```

* 64: Number of sequences in the batch.
* 60: Window size.
* 1: Number of features, which is the closing price.

Therefore:

> **An RNN maintains a hidden state, an LSTM maintains both a hidden state and a cell state, while a GRU maintains a hidden state and uses update and reset gates to control information flow.**

The GRU has a simpler structure than the LSTM because it does not maintain a separate cell state and uses only two gates.

The main concepts are:

1. GRU is a specialized recurrent neural network.
2. GRU maintains a **hidden state**.
3. GRU uses an **update gate** and a **reset gate**.
4. GRU does not have a separate cell state.
5. The input shape remains:

```text
(batch_size, window_size, feature_size)
```

# 2. Creating the GRU Model

We can implement the model using PyTorch.

```python
import torch
import torch.nn as nn
```

The model is:

```python
class GRUModel(nn.Module):

    def __init__(
        self,
        feature_size=1,
        hidden_size=128,
        horizon=1
    ):
        super().__init__()

        self.gru = nn.GRU(
            input_size=feature_size,
            hidden_size=hidden_size,
            num_layers=1,   # Number of GRU layers
            batch_first=True
        )

        self.fc = nn.Linear(
            hidden_size,
            horizon
        )


    def forward(self, x):

        # GRU output
        output, hidden = self.gru(x)

        # Select the output from
        # the last time step
        output = output[:, -1, :]

        # Output layer
        output = self.fc(output)

        return output
```

### `feature_size`

```python
feature_size = 1
```

because our dataset has only one feature:

```text
Close Price
```

### `hidden_size`

```python
hidden_size = 128
```

This specifies the size of the hidden state.

The GRU therefore maintains a hidden representation containing 128 values at each time step.

Unlike an LSTM, there is no separate cell state.

### `num_layers`

We use:

```python
num_layers = 1
```

This means that our model contains **one GRU layer**.

If we used:

```python
num_layers = 2
```

there would be two stacked GRU layers.

### `batch_first=True`

We use:

```python
batch_first=True
```

so PyTorch expects:

```text
(batch_size, window_size, feature_size)
```

rather than:

```text
(window_size, batch_size, feature_size)
```

For our model:

```text
(64, 60, 1)
```

means:

```text
64 → number of sequences in the batch
60 → number of time steps
1  → number of features at each time step
```

## 2.1 Hidden State

Unlike an LSTM, the GRU maintains only a **hidden state**.

The GRU returns:

```python
output, hidden = self.gru(x)
```

The `hidden` tensor contains the final hidden state.

The `output` tensor contains the hidden representation for **every time step**.

The output tensor has the shape:

```text
(batch_size, window_size, hidden_size)
```

With our configuration:

```text
(64, 60, 128)
```

For next-step forecasting, we use the output from the **last time step**:

```python
output = output[:, -1, :]
```

The shape becomes:

```text
(64, 128)
```

Then the linear layer converts:

```text
128 → 1
```

giving:

```text
(64, 1)
```

This represents one predicted future price for each sequence in the batch.

# 3. Preparing Data for the GRU

Our existing sliding-window function can still be used.

Or from the section 22 We can call ```create_sliding_windows``` function as follow to create sliding window:

For example:

```python
window_size = 60
```

```python

X_test, y_test = create_sliding_windows(
    test_values,
    window_size=window_size,
    horizon=horizon

```


The sliding-window function produces:

```text
X_train
    ↓
(number_of_samples, 60)

y_train
    ↓
(number_of_samples, 1)
```

However, the GRU needs:

```text
(number_of_samples, 60, 1)
```

Therefore, we need to add the feature dimension.

We can use:

```python
X_train = X_train.reshape(X_train.shape[0], X_train.shape[1], 1)
```

Similarly:

```python
X_test = X_test.reshape(X_test.shape[0], X_test.shape[1], 1)
```

Now:

```text
Before:

X_train
(samples, 60)


After:

X_train
(samples, 60, 1)
```

The final dimension represents the single feature:

```text
Close Price
```

## 4.1 Loss Function

As in our FFNN, RNN, and LSTM models, we use **Mean Absolute Error (MAE)**.

In PyTorch:

```python
criterion = nn.L1Loss()
```

MAE measures the average absolute difference between the actual and predicted prices.

## 4.2 Adam Optimizer

We use the **Adam optimizer**:

```python
optimizer = torch.optim.Adam(
    model_GRU.parameters(),
    lr=0.01
)
```

Adam updates the GRU's parameters during training based on the gradients calculated during backpropagation.

## 4.3 Training the GRU

Because we already created a general `train_model()` function, we do not need to write another training loop specifically for the GRU.

We can reuse the same function:

```python
train_losses_GRU, test_losses_GRU = train_model(
    model=model_GRU,
    train_loader=train_loader,
    test_loader=test_loader,
    criterion=criterion,
    optimizer=optimizer,
    epochs=100
)
```

For time-series regression, the important metrics are the **loss values and forecasting errors** rather than classification accuracy.

Therefore, although our general training function may retain the accuracy variables for consistency with previous tutorials, they are not meaningful for Bitcoin price regression.
