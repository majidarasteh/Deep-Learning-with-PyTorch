# 1. Time-Series Forecasting Using LSTM

In the previous lecture, we built a **Recurrent Neural Network (RNN)** for Bitcoin price forecasting.

The RNN receives a fixed window of historical closing prices and processes them sequentially to predict the next price.

A **Long Short-Term Memory (LSTM)** network is a special type of recurrent neural network designed to handle this problem more effectively.

LSTM uses a **cell state** and several **gates** to control what information should be:

* forgotten,
* stored,
* and passed to the next time step.

Therefore, LSTM can be particularly useful when important information from earlier time steps needs to be preserved.


## 1.1 Basic Idea of an LSTM

An LSTM extends the basic RNN idea by maintaining two types of state:

```text
Hidden State
     hₜ

Cell State
     cₜ
```

The **hidden state** contains information used to produce the current output.

The **cell state** acts as a long-term memory pathway that allows important information to be carried across time steps.

LSTM uses **a cell state and several gates** to control what information should be:

* forgotten
* stored
* and passed to the next time step.

Therefore, LSTM can be particularly useful when important information from earlier time steps needs to be preserved.

The important idea is:

> The LSTM learns which information should be forgotten, which new information should be stored, and which information should be used to produce the current hidden state.


## 1.2 LSTM Gates

The main difference between a basic RNN and an LSTM is the use of **gates**.

An LSTM contains three main gates:

1. **Forget Gate**
2. **Input Gate**
3. **Output Gate**

These gates control the flow of information.

### Forget Gate

The forget gate determines which information from the previous cell state should be retained or discarded.

The forget gate uses a sigmoid activation function, producing values between 0 and 1.

```text
0 → forget completely
1 → keep completely
```

### Input Gate

The input gate determines which new information should be stored in the cell state.

The network therefore learns which parts of the current observation are important enough to remember.


### Output Gate

The output gate determines which information from the cell state should be used to produce the current hidden state.

The hidden state is then passed to the next time step and can also be used to make the final prediction.

## 1.3 LSTM Architecture

For our time-series forecasting problem, the overall architecture is:

```text
Input
(batch_size, window_size, 1)
            │
            ▼
          LSTM
      hidden_size=128
            │
            ▼
       Last Time Step
            │
            ▼
        Linear Layer
         128 → 1
            │
            ▼
      Predicted Price
```

For our current configuration:

```text
Input
(64, 60, 1)
    │
    ▼
LSTM
hidden_size = 128
    │
    ▼
Last Time Step
(64, 128)
    │
    ▼
Linear
128 → 1
    │
    ▼
Prediction
(64, 1)
```

* 64: Number of batches.
* 60: Window Size
* 1: Is the number of features (here we have just close price).


Therefore:

> **An RNN maintains a hidden state, while an LSTM maintains both a hidden state and a cell state and uses gates to control the flow of information.**

A basic RNN may struggle to preserve information over long sequences because of the vanishing-gradient problem.

LSTM addresses this limitation using its memory mechanism and gates. The main concepts were:

1. LSTM is a specialized recurrent neural network.
2. LSTM maintains both a **hidden state** and a **cell state**.
3. LSTM uses **forget, input, and output gates** to control information flow.

# 2. Creating the LSTM Model

We can implement the model using PyTorch.

```python
import torch
import torch.nn as nn
```

The model is:

```python
class LSTMModel(nn.Module):

    def __init__(
        self,
        feature_size=1,
        hidden_size=128,
        horizon=1
    ):
        super().__init__()

        self.lstm = nn.LSTM(
            input_size=feature_size,
            hidden_size=hidden_size,
            num_layers=1,   # Number of LSTM layers
            batch_first=True
        )

        self.fc = nn.Linear(
            hidden_size,
            horizon
        )


    def forward(self, x):

        # LSTM output
        output, (hidden, cell) = self.lstm(x)

        # Select the output from
        # the last time step
        output = output[:, -1, :]

        # Output layer
        output = self.fc(output)

        return output
```

The important part is:

```python
self.lstm = nn.LSTM(
    input_size=feature_size,
    hidden_size=hidden_size,
    num_layers=1,
    batch_first=True
)
```

### `feature_size`

```python
feature_size = 1
```

because our dataset has only one feature:

```text
Close Price
```

### `hidden_size`

```python
hidden_size = 128
```

This specifies the size of the hidden state.

The LSTM therefore maintains a hidden representation containing 128 values at each time step.

The cell state also has the same hidden size:

```text
hidden state → 128 values
cell state   → 128 values
```

### `num_layers`

We use:

```python
num_layers = 1
```

This means that our model contains **one LSTM layer**.

If we used:

```python
num_layers = 2
```

there would be two stacked LSTM layers.

### `batch_first=True`

We use:

```python
batch_first=True
```

so PyTorch expects:

```text
(batch_size, window_size, feature_size)
```

rather than:

```text
(window_size, batch_size, feature_size)
```

This makes the input representation easier to understand.

For our model:

```text
(64, 60, 1)
```

means:

```text
64 → number of sequences in the batch
60 → number of time steps
1  → number of features at each time step
```

## 2.1 Why Is `window_size` Not Used When Creating the LSTM?

As with the RNN, we do **not** write:

```python
window_size = 60
```

inside the `LSTMModel`.

This does not mean that the window size is unimportant.

The window size determines the **sequence length of the input data**, not the structure of the LSTM layer.

For example:

```python
window_size = 60
```

creates sequences containing:

```text
x₁ → x₂ → x₃ → ... → x₆₀
```

The resulting input has the shape:

```text
(batch_size, 60, feature_size)
```

The LSTM receives this tensor and automatically determines the sequence length from the input.

## 2.2 Hidden State and Cell State

Unlike a basic RNN, an LSTM returns two states:

```python
output, (hidden, cell) = self.lstm(x)
```

The two states are:

```text
hidden
cell
```

The **hidden state** represents the current working information of the LSTM.

The **cell state** acts as the long-term memory of the LSTM.

The LSTM produces an output for **every time step**.

The output tensor has the shape:

```text
(batch_size, window_size, hidden_size)
```

With our configuration:

```text
(64, 60, 128)
```

For next-step forecasting, we use the output from the **last time step**:

```python
output = output[:, -1, :]
```

The shape becomes:

```text
(64, 128)
```

Then the linear layer converts:

```text
128 → 1
```

giving:

```text
(64, 1)
```

This represents one predicted future price for each sequence in the batch.


## 4.6 Predicting the Next Bitcoin Price

Our previous prediction function was designed for the FFNN input shape:

```text
(1, window_size)
```

The LSTM requires:

```text
(1, window_size, 1)
```

Therefore, we create an LSTM-specific prediction function:

```python
def predict_next_price_LSTM(
    model,
    data,
    window_size
):
    """
    Predict the next value using an LSTM.
    """

    # Set model to evaluation mode
    model.eval()

    # Get the latest window
    input_data = data[-window_size:]

    # Convert to NumPy
    input_data = np.asarray(
        input_data,
        dtype=np.float32
    )

    # Convert to tensor
    input_tensor = torch.tensor(
        input_data,
        dtype=torch.float32
    )

    # Reshape:
    # (window_size)
    #       ↓
    # (1, window_size, 1)
    input_tensor = input_tensor.reshape(
        1,
        window_size,
        1
    )

    # Move to device
    input_tensor = input_tensor.to(device)

    # Make prediction
    with torch.no_grad():

        prediction = model(
            input_tensor
        )

    # Return a single value
    return prediction.item()
```
