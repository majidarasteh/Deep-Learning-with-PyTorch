
# 1. Recurrent Neural Networks for Text Classification

In the section **12. NLP: Tokenization and Embeddings**, we introduced the first steps required for building a text classification system. We learned how to load the SMS Spam Collection dataset, explore the data, and create training and testing datasets. Furthermore, we became familiar with the fundamental concepts of **text preprocessing**, including tokenization, vocabulary construction, converting text into numerical representations, padding, and truncation. Finally, we introduced **word embeddings** and learned how embedding layers transform token IDs into dense vector representations that can be processed by neural networks.

In the section **13. NLP: Feed-Forward Neural Networks for Text Classification**, we introduced a baseline neural network model for SMS spam classification. We learned how to combine an embedding layer with a **Feed-Forward Neural Network (FFNN)** and trained the model to classify messages into two categories: **ham** and **spam**. Although the FFNN model can learn useful patterns from text representations, it has an important limitation: it treats the input representation as a fixed collection of features and does not consider the sequential structure of language. Therefore, the model cannot explicitly understand the order of words or the dependencies between different parts of a sentence.

Considering the concepts introduced in the previous sections, in this section we introduce **Recurrent Neural Networks (RNNs) for Text Classification**. RNNs are designed specifically for processing sequential data and can maintain information from previous elements through a mechanism called the **hidden state**. Unlike a feed-forward network, an RNN processes words one by one and updates its internal memory as it reads the sequence. This ability allows RNNs to capture contextual information and word dependencies, making them more suitable for many natural language processing tasks.

The overall text classification pipeline using an RNN is illustrated below:

```text
SMS Message

      ↓

Tokenization

      ↓

Token IDs

      ↓

Embedding Layer

      ↓

Recurrent Neural Network

      ↓

Final Hidden State

      ↓

Fully Connected Layer

      ↓

Spam / Ham Prediction
```

Unlike the FFNN model introduced in the previous section, where all word embeddings were combined using average pooling before classification, the RNN processes the sequence step by step. At each time step, the network receives the current word embedding and combines it with information stored from previous words. This allows the model to build a representation that contains information about the entire sentence.

By the end of this section, we will have developed a deeper understanding of how neural networks can process sequential text data and why recurrent architectures became one of the fundamental approaches in natural language processing before the emergence of more advanced models such as Transformers.


## 1.1 The Importance of Sequential Information in Text

Text data has a natural sequential structure. The meaning of a sentence is not determined only by the words it contains, but also by the order in which those words appear.

For example, consider the following two sentences:

```text
The movie was good.
```

and

```text
The movie was not good.
```

Both sentences contain many identical words:

```text
The, movie, was, good
```

However, their meanings are completely different because of the position of the word:

```text
not
```

A model that ignores word order may incorrectly treat these two sentences as similar.

The same problem exists in SMS spam classification. Consider the following examples:

```text
You won a free prize.
```

and

```text
You did not win a free prize.
```

The presence of words such as:

```text
win
free
prize
```

may indicate spam, but their interpretation depends on the surrounding words.

Therefore, an effective text classification model should not only learn which words appear in a message but also understand how words interact with each other in a sequence.


## 2.2 Limitation of Feed-Forward Neural Networks

In the previous section, we implemented a Feed-Forward Neural Network using the following architecture:

```text
Token IDs

     ↓

Embedding Layer

     ↓

Average Pooling

     ↓

Fully Connected Layers

     ↓

Prediction
```

The embedding layer converts each token into a dense vector:

```text
word1 → vector1

word2 → vector2

word3 → vector3
```

The average pooling operation then combines all word embeddings into a single vector:

```text
(vector1 + vector2 + vector3) / 3
```

Although this approach creates a fixed-size representation of the sentence, it removes the order information.

For example:

```text
I love machine learning
```

and

```text
Machine learning love I
```

would produce similar averaged representations, even though the second sentence is not meaningful English.

Therefore, FFNNs have no mechanism to remember previous words or understand the relationship between different positions in a sequence.

To overcome this limitation, we need a model with memory. This leads us to **Recurrent Neural Networks**.
