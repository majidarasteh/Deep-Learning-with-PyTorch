
# 1. Recurrent Neural Networks for Text Classification

In the section **12. NLP: Tokenization and Embeddings**, we introduced the first steps required for building a text classification system. We learned how to load the SMS Spam Collection dataset, explore the data, and create training and testing datasets. Furthermore, we became familiar with the fundamental concepts of **text preprocessing**, including tokenization, vocabulary construction, converting text into numerical representations, padding, and truncation. Finally, we introduced **word embeddings** and learned how embedding layers transform token IDs into dense vector representations that can be processed by neural networks.

Although the FFNN model can learn useful patterns from text representations, it has an important limitation: it treats the input representation as a fixed collection of features and does not consider the sequential structure of language. RNNs are designed specifically for processing sequential data and can maintain information from previous elements through a mechanism called the **hidden state**. Unlike a feed-forward network, an RNN processes words one by one and updates its internal memory as it reads the sequence. This ability allows RNNs to capture contextual information and word dependencies, making them more suitable for many natural language processing tasks.

The overall text classification pipeline using an RNN is illustrated below:

```text

      ↓

Token IDs

      ↓

Embedding Layer

      ↓

Recurrent Neural Network

      ↓

Final Hidden State

      ↓

Fully Connected Layer

      ↓

```

Unlike the FFNN model introduced in the previous section, where all word embeddings were combined using average pooling before classification, the RNN processes the sequence step by step. At each time step, the network receives the current word embedding and combines it with information stored from previous words. This allows the model to build a representation that contains information about the entire sentence.

By the end of this section, we will have developed a deeper understanding of how neural networks can process sequential text data and why recurrent architectures became one of the fundamental approaches in natural language processing before the emergence of more advanced models such as Transformers.


## 1.1 The Importance of Sequential Information in Text

Text data has a natural sequential structure. The meaning of a sentence is not determined only by the words it contains, but also by the order in which those words appear.

For example, consider the following two sentences:

```text
The movie was good.
```

and

```text
The movie was not good.
```

Both sentences contain many identical words:

```text
The, movie, was, good
```

However, their meanings are completely different because of the position of the word:

```text
not
```

A model that ignores word order may incorrectly treat these two sentences as similar.

The same problem exists in SMS spam classification. Consider the following examples:

```text
You won a free prize.
```

and

```text
You did not win a free prize.
```

The presence of words such as:

```text
win
free
prize
```

may indicate spam, but their interpretation depends on the surrounding words.

Therefore, an effective text classification model should not only learn which words appear in a message but also understand how words interact with each other in a sequence.


## 1.2 Limitation of Feed-Forward Neural Networks

In the previous section, we implemented a Feed-Forward Neural Network using the following architecture:

```text
Token IDs

     ↓

Embedding Layer

     ↓

Average Pooling

     ↓

Fully Connected Layers

     ↓

Prediction
```

The embedding layer converts each token into a dense vector:

```text
word1 → vector1

word2 → vector2

word3 → vector3
```

The average pooling operation then combines all word embeddings into a single vector:

```text
(vector1 + vector2 + vector3) / 3
```

Although this approach creates a fixed-size representation of the sentence, it removes the order information.

For example:

```text
I love machine learning
```

and

```text
Machine learning love I
```

would produce similar averaged representations, even though the second sentence is not meaningful English.

Therefore, FFNNs have no mechanism to remember previous words or understand the relationship between different positions in a sequence.

To overcome this limitation, we need a model with memory. This leads us to **Recurrent Neural Networks**.

# 2 Basic Concept of Recurrent Neural Networks

A **Recurrent Neural Network (RNN)** is a type of neural network designed to process sequential data. Unlike a Feed-Forward Neural Network, which processes each input independently, an RNN maintains a memory of previous inputs through a variable called the **hidden state**.

The main idea behind an RNN is simple:

> The current output is influenced not only by the current input but also by information learned from previous inputs.

In text classification, each word in a sentence is processed sequentially. The RNN reads one word at a time and updates its hidden state after each word. The hidden state acts as a memory that stores important information from the previous part of the sentence.

Consider the following SMS message:

```text
Congratulations you won free money
```

After tokenization and embedding, the sentence is represented as a sequence of word embeddings:

```text
x1              x2       x3      x4      x5

Congratulations you      won     free    money
```

where each (x_t) represents the embedding vector of the word at position (t).

The RNN processes this sequence step by step.

At the first time step:

```text
x1 → RNN → h1
```

The network receives the first word and creates an initial hidden state.

At the second time step:

```text
x2 + h1 → RNN → h2
```

The RNN receives the second word together with the previous hidden state. The new hidden state now contains information about both the first and second words.

This process continues until the end of the sentence:

```text
x5 + h4 → RNN → h5
```

The final hidden state (h_5) contains information about the entire SMS message.

For classification, we use this final hidden state as a representation of the complete sentence:

```text
Final Hidden State

        ↓

Fully Connected Layer

        ↓

Spam Probability
```

Therefore, instead of simply averaging word embeddings as in the FFNN model, the RNN learns a representation that considers the order and relationship between words.


## 2.1 Recurrent Neural Network Architecture

The complete architecture of an RNN-based text classifier is shown below:

```text
SMS Message

      ↓

Tokenization

      ↓

Token IDs

      ↓

Embedding Layer

      ↓

Sequence of Word Embeddings

      ↓

Recurrent Neural Network

      ↓

Final Hidden State

      ↓

Linear Layer

      ↓

Spam Probability
```

Each component has a specific role:

### 1. Tokenization

The raw text is converted into integer token IDs.

Example:

```text
"free money"

        ↓

[25, 91]
```

### 2. Embedding Layer

The token IDs are transformed into dense vectors.

Example:

```text
25 → [0.21, -0.14, 0.52, ...]

91 → [0.34, 0.08, -0.11, ...]
```

The output of the embedding layer is a sequence of vectors:

$[
X = (x_1,x_2,...,x_T)
]$

where ($T$) is the sequence length.


### 3. Recurrent Neural Network

The RNN reads the embedding vectors sequentially and updates the hidden state:

$[
h_1,h_2,...,h_T
]$

Each hidden state contains information from the current word and previous words.

### 4. Classification Layer

The final hidden state is passed to a fully connected layer that produces the prediction.

For binary classification:

$[
y = W h_T + b
]$

where:

* ($h_T$) is the final hidden state.
* ($W$) is the weight matrix.
* ($b$) is the bias term.
* ($y$) is the output logit.

The logit is converted into a probability using the sigmoid function:

$[
P(spam)=\sigma(y)
]$

where:

* probability close to 1 indicates spam.
* probability close to 0 indicates ham.


## 2.2 Mathematical Formulation of an RNN

At each time step, an RNN updates its hidden state using the current input and the previous hidden state.

The basic RNN equation is:

$[
h_t = tanh(W_xx_t + W_hh_{t-1}+b)
]$

where:

| Symbol    | Description                             |
| --------- | --------------------------------------- |
| ($x_t$)     | Input vector at time step (t)           |
| ($h_t$)     | Current hidden state                    |
| ($h_{t-1}$) | Previous hidden state                   |
| ($W_x$)     | Weight matrix for current input         |
| ($W_h$)     | Weight matrix for previous hidden state |
| ($b$)       | Bias vector                             |
| ($tanh$)    | Activation function                     |

The equation contains two important terms:

### Current input information

$[
W_xx_t
]$

This term represents the information coming from the current word.

For example:

```text
free
```

may provide information related to spam.


### Previous context information

$[
W_hh_{t-1}
]$

This term represents information learned from previous words.

For example:

```text
not free
```

has a different meaning from:

```text
free
```

because the previous word changes the interpretation.

The RNN combines these two sources of information to update its memory.

### Time step 2

## 2.3 RNN Input and Output Shapes

Understanding tensor dimensions is essential when implementing RNNs in PyTorch.

Assume:

```python
batch_size = 32
```

Each batch contains:

* 32 SMS messages
* Each message has 30 tokens
* Each token is represented by a 128-dimensional embedding vector


### Input to the Embedding Layer

Before embedding:

```text

```

Example:

```text

```

Each value represents a token ID.


### Output of the Embedding Layer

After embedding:

```text

```

Example:

```text

```

The meaning is:

* 32 messages
* 30 words per message
* 128 values per word vector


### Output of the RNN Layer

The RNN produces two outputs:

```python

```

#### Output

The output contains hidden states from all time steps:

```text
(batch_size, sequence_length, hidden_dim)
```

Example:

```text
(32,30,64)
```

It contains:

```text

```

for every sentence.


#### Hidden State

The hidden state contains the final hidden representation:

```text
(num_layers, batch_size, hidden_dim)
```

For a single-layer RNN:

```text
(1,32,64)
```

The first dimension represents the number of RNN layers.

For classification, we usually use only the final hidden state:

```text
(32,64)
```

after removing the first dimension.


# 3. Implementing an RNN-Based Text Classifier Using PyTorch

PyTorch provides the `nn.RNN` module for implementing recurrent neural networks.

The general structure of our model is:


### 1. Embedding Layer

The first layer converts integer token IDs into dense vectors.

For example, if the input contains:

```text
[25, 91, 17, 0, 0]
```

the embedding layer converts it into:

```text
[
 [0.21, -0.14, 0.52, ...],
 [0.34,  0.08, -0.11, ...],
 [0.17,  0.32, 0.45, ...],
 [0,0,0,...],
 [0,0,0,...]
]
```

The output shape becomes:

```text
(batch_size, sequence_length, embedding_dim)
```

Example:

```text
(32,30,128)
```


### 2. RNN Layer

The RNN receives the sequence of embeddings and processes them one by one.

The input:

```text
x1,x2,x3,...,x30
```

is transformed into hidden states:

```text
h1,h2,h3,...,h30
```

The final hidden state:

```text
h30
```

contains information about the complete SMS message.


### 3. Fully Connected Layer

The final hidden state is passed to a linear layer:

$[
y = Wh+b
]$

where:

* ($h$) is the final hidden state.
* ($W$) is the learnable weight matrix.
* ($b$) is the bias.
* ($y$) is the output logit.

Because this is a binary classification problem, the output contains only one value.

Example:

```text
0.85
```

This value is called a **logit**.

During prediction, the logit is converted into a probability using the sigmoid function:

$[
P(spam)=\sigma(y)
]$

## 3.2 Creating the RNN Model

PyTorch provides the `nn.RNN` module for implementing recurrent neural networks. The implementation is shown below:

```python
# Implement an RNN

import torch
import torch.nn as nn


class RNNClassifier(nn.Module):

    def __init__(
        self,
        vocab_size,
        embedding_dim,
        hidden_dim
    ):

        super().__init__()

        # Word embedding layer
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )


        # Recurrent Neural Network layer
        self.rnn = nn.RNN(
            input_size=embedding_dim,
            hidden_size=hidden_dim,
            batch_first=True
        )


        # Fully connected classification layer
        self.fc = nn.Linear(
            in_features=hidden_dim,
            out_features=1
        )

        # Sigmoid activation
        self.sigmoid = nn.Sigmoid()


    def forward(self, x):

        # Convert token IDs into embeddings
        x = self.embedding(x)


        # Process the sequence using RNN
        output, hidden = self.rnn(x)


        # Remove the first dimension
        hidden = hidden.squeeze(0)


        # Convert hidden representation into prediction
        output = self.fc(hidden)

        # Convert logits to probability
        output = self.sigmoid(output)

        return output
```


### 3.2 1 Understanding the RNN Parameters

#### `input_size`

```python
input_size=embedding_dim
```

The RNN receives word embeddings as input.

If:

```python
embedding_dim = 128
```

then every word is represented by a vector containing 128 values.

Therefore, the RNN input size is:

```text
input_size = 128
```

#### `hidden_size`

```python
hidden_size=hidden_dim
```

The hidden size determines the dimension of the RNN's memory vector.

The hidden state is the representation that stores information learned from previous words.

For example:

```python
hidden_dim = 64
```

means that the RNN represents each SMS message using a 64-dimensional hidden vector.

The larger the hidden dimension:

* the more information the model can store,
* but the more parameters and computational cost are required.

For small datasets such as SMS Spam Collection, a value such as:

```python
hidden_dim = 64
```

provides a good balance between model capacity and efficiency.


### 3.2.2 Understanding `batch_first=True`

The parameter:

```python
batch_first=True
```

defines the order of dimensions in the input tensor.

By default, PyTorch expects RNN input in the following format:

```text
(sequence_length, batch_size, embedding_dim)
```

For example:

```text
(30, 32, 128)
```

where:

* 30 → number of tokens
* 32 → number of SMS messages
* 128 → embedding dimension

However, PyTorch DataLoader naturally creates batches in the format:

```text
(batch_size, sequence_length)
```

After embedding:

```text
(batch_size, sequence_length, embedding_dim)
```

Therefore, using:

```python
batch_first=True
```

allows us to directly use:

```text
(32, 30, 128)
```

without manually changing the tensor dimensions.

This makes the code easier to understand and is commonly used in practical PyTorch projects.


### 3.2.3 Understanding the Fully Connected Layer

The final layer of the model is:

```python
self.fc = nn.Linear(
    in_features=hidden_dim,
    out_features=1
)
```

This layer converts the RNN hidden representation into a single prediction value.

For example, if:

```python
hidden_dim = 64
```

the RNN produces:

```text
hidden state:

[
0.21,
-0.15,
0.44,
...
64 values
]
```

The fully connected layer transforms:

```text
64 features

       ↓

Linear Layer

       ↓

1 output value
```

The reason we use:

```python
out_features=1
```

is that this is a **binary classification problem**:

```text
ham  → 0

spam → 1
```

Therefore, one output value is sufficient.


### 3.2.4 Understanding `output = self.fc(hidden)`

The statement:

```python
output = self.fc(hidden)
```

applies the fully connected layer to the final RNN hidden state.

Before this operation:

```python
hidden.shape
```

is:

```text

```

For example:

```text
(32,64)
```

meaning:

* 32 SMS messages
* each represented by 64 learned features

After:

```python

```

the shape becomes:

```text
(32,1)
```

Example:

```text
output:

[
 [ 2.31 ],
 [-1.25 ],
 [ 0.87 ],
 ...
]
```

Each value is a **logit**, which represents the model's confidence before converting it into a probability.

Later, during prediction:

```python

```

converts the logit into a value between 0 and 1:

```text
0.0 → ham
```

### 3.4.1 Defining Loss Function and Optimizer

Since the model contains a sigmoid activation function, its output is already a probability value between 0 and 1. Therefore, we use **Binary Cross-Entropy Loss (`BCELoss`)**.

```python
import torch.optim as optim

criterion = nn.BCELoss()

optimizer = optim.Adam(
    model.parameters(),
    lr=0.001
)
```

The `BCELoss` compares the predicted probability with the true label.

### 3.4.3 Understanding the Training Process

During each epoch, the following steps are performed:

#### 1. Forward Pass

A batch of SMS messages is passed through the model.

For example, with a batch size of 32:


* 32 SMS messages
* each containing 30 token IDs

After embedding:


#### 2. Loss Calculation

The predicted probabilities are compared with the real labels:

Example:


The Binary Cross-Entropy loss measures how close the predictions are to the correct labels.

#### 3. Backpropagation

The loss value is used to calculate gradients:


These gradients indicate how each model parameter should be adjusted to reduce future errors.

#### 4. Parameter Update

The Adam optimizer updates the model weights:

```python

```

This process is repeated for all mini-batches until the complete training dataset has been processed.
