
# 1. NLP: Convolutional Neural Networks for Text Classification (TextCNNs)

In this section, we introduce **Convolutional Neural Networks (CNNs) for Text Classification**, commonly referred to as **TextCNNs**.

CNNs were originally developed for image processing, where convolutional filters are used to detect local patterns such as edges and textures. The same fundamental idea can be applied to text. Instead of detecting visual patterns, a one-dimensional convolutional layer can detect **local patterns of words**, such as:

```text
"free prize"
"win money"
"call now"
"limited offer"
```

These short sequences of words can be highly informative for SMS spam classification. 

Unlike RNN, LSTM, and GRU models, the TextCNN does not need to process the sequence one word at a time. Instead, convolutional filters examine multiple words simultaneously and learn useful local patterns.

Before discussing the implementation, it is important to understand why CNNs can be useful for natural language processing.

## 1.1 Local Patterns in Text

Many text classification problems depend heavily on short sequences of words.

For example, consider the following SMS messages:

```text
You won a free prize
```

and

```text
Congratulations! You have won money
```

Certain combinations of neighboring words provide strong clues about the class of the message.

Examples include:

```text
free prize
won money
claim now
call now
special offer
```

These patterns can be considered **local features**.

A CNN is particularly effective at detecting such local patterns.

Instead of processing:

```text
You → won → a → free → prize
```

one word at a time, a CNN can examine groups of neighboring words:

```text
You won a
won a free
a free prize
```

and learn which combinations are useful for classification.


## 1.2 CNNs and N-grams

The concept of local patterns in TextCNNs is closely related to **n-grams**.

An n-gram is a sequence of `n` consecutive tokens.

For example:

```text
You won a free prize
```

contains the following bigrams:

```text
You won
won a
a free
free prize
```

and trigrams:

```text
You won a
won a free
a free prize
```

A convolutional filter can learn patterns that are conceptually similar to these n-grams.

For example:

```text
Filter size = 2
```

can examine two neighboring words at a time.

A filter with:

```text
Filter size = 3
```

can examine three neighboring words.

Therefore, multiple convolutional filters can learn patterns corresponding to different lengths of phrases.


# 2. Basic Concept of TextCNN

A TextCNN typically consists of four important components:

1. **Embedding Layer**
2. **Convolutional Layer**
3. **Pooling Layer**
4. **Fully Connected Classification Layer**

The basic architecture is:

```text
Token IDs
    ↓
Embedding
    ↓
Word Embedding Sequence
    ↓
Convolution
    ↓
Activation
    ↓
Max Pooling
    ↓
Feature Vector
    ↓
Fully Connected Layer
    ↓
Sigmoid
    ↓
Prediction
```

Let's examine each component.

## 2.1 Embedding Layer

As in our previous models, the first step is to convert token IDs into dense vectors.

Suppose an SMS contains 30 tokens and each word is represented using a 128-dimensional embedding.

The input is:

```text
(batch_size, sequence_length)
```

For example:

```text
(32, 30)
```

After the embedding layer:

```text
(32, 30, 128)
```

This means:

```text
32 SMS messages
30 tokens per message
128-dimensional embedding for each token
```

Conceptually:

```text
Word 1 → [128 values]
Word 2 → [128 values]
Word 3 → [128 values]
...
Word 30 → [128 values]
```

The embedding layer therefore converts the original token sequence into a numerical representation that can be processed by the CNN.


## 2.2 Convolutional Layer

The main component of TextCNN is the **one-dimensional convolutional layer**.

PyTorch provides:

```python
nn.Conv1d
```

for one-dimensional convolution.

A convolutional filter moves across the sequence and examines neighboring word embeddings.

For example, suppose we use a filter size of 3.

The filter examines:

```text
Word 1
Word 2
Word 3
```

then:

```text
Word 2
Word 3
Word 4
```

then:

```text
Word 3
Word 4
Word 5
```

and so on.

This allows the filter to learn useful three-word patterns.

Conceptually:

```text
Word 1 ─┐
Word 2 ─┼──► Convolution Filter ──► Feature
Word 3 ─┘
```

The filter then moves to the next position:

```text
Word 2 ─┐
Word 3 ─┼──► Convolution Filter ──► Feature
Word 4 ─┘
```

This process continues across the entire sequence.


## 2.3 Different Filter Sizes

One of the most useful properties of TextCNN is that we can use multiple filter sizes.

For example:

```text
Filter size = 2
Filter size = 3
Filter size = 4
```

These filters can learn patterns of different lengths.

Conceptually:

```text
2-word patterns:
"free prize"

3-word patterns:
"you won money"

4-word patterns:
"claim your free prize"
```

Therefore, using multiple filter sizes allows the model to capture both short and longer local patterns.

## 2.4 Activation Function

After convolution, we apply a nonlinear activation function.

A commonly used activation function is **ReLU**:

```python
nn.ReLU()
```

The ReLU function is defined as:

[
ReLU(x)=\max(0,x)
]

It replaces negative values with zero while preserving positive values.

Therefore:

```text
Convolution
     ↓
ReLU
     ↓
Feature Map
```

The ReLU activation allows the network to learn nonlinear patterns from the extracted text features.

## 2.5 Max Pooling

After convolution and activation, the resulting feature map may still contain multiple values corresponding to different positions in the sentence.

We can use **max pooling** to select the strongest feature.

For example:

```text
Feature map:

[0.2, 0.8, 0.1, 0.4, 1.5, 0.3]
```

Max pooling selects:

```text
1.5
```

The idea is that if a particular feature strongly indicates spam, its position in the sentence may not be important. We mainly need to know whether that feature appeared somewhere in the message.

For text classification, this is particularly useful.

For example, if a convolutional filter learns to detect:

```text
free prize
```

then it does not matter whether the phrase appears at the beginning:

```text
free prize is waiting for you
```

or near the end:

```text
Congratulations, you have won a free prize
```

The maximum activation can capture the strongest occurrence.

## 2.6 Feature Concatenation

If we use several convolutional filters with different kernel sizes, each produces its own pooled feature vector.

For example:

```text
Conv(2) → Max Pooling → 64 features

Conv(3) → Max Pooling → 64 features

Conv(4) → Max Pooling → 64 features
```

We can concatenate them:

```text
64 + 64 + 64 = 192 features
```

The resulting vector represents the most important local patterns detected by the CNN.

This vector is then passed to the fully connected classification layer.


# 3. TextCNN Architecture

The complete architecture can be represented as:

```text
                    Token IDs
                       │
                       ▼
                 Embedding Layer
                       │
                       ▼
              Word Embedding Matrix
                       │
        ┌──────────────┼──────────────┐
        │              │              │
        ▼              ▼              ▼
    Conv-2          Conv-3         Conv-4
        │              │              │
        ▼              ▼              ▼
      ReLU           ReLU           ReLU
        │              │              │
        ▼              ▼              ▼
   Max Pooling    Max Pooling    Max Pooling
        │              │              │
        └──────────────┼──────────────┘
                       │
                       ▼
                 Concatenation
                       │
                       ▼
              Fully Connected Layer
                       │
                       ▼
                    Sigmoid
                       │
                       ▼
                Spam Probability
```

This architecture allows the model to learn different types of local patterns from the SMS message.


# 4. Implementing TextCNN Using PyTorch

PyTorch provides the `nn.Conv1d` module for one-dimensional convolution.

Before implementing the model, we need to understand an important difference between the shape produced by the embedding layer and the shape expected by `nn.Conv1d`.

The embedding layer produces:

```text
(batch_size, sequence_length, embedding_dim)
```

For example:

```text
(32, 30, 128)
```

However, `nn.Conv1d` expects:

```text
(batch_size, channels, sequence_length)
```

Therefore, we need to rearrange the dimensions:

```text
(32, 30, 128)
        ↓
(32, 128, 30)
```

In PyTorch, this can be done using:

```python
x = x.permute(0, 2, 1)
```

Here:

```text
0 → batch dimension
2 → embedding dimension
1 → sequence dimension
```

Thus:

```text
(batch, sequence, embedding)
```

becomes:

```text
(batch, embedding, sequence)
```


## 4.1 Creating the TextCNN Model

We can implement the TextCNN classifier as follows:

```python
import torch
import torch.nn as nn


class TextCNNClassifier(nn.Module):

    def __init__(
        self,
        vocab_size,
        embedding_dim,
        num_filters,
        filter_sizes
    ):

        super().__init__()

        # Word embedding layer
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )

        # Convolutional layers
        self.convs = nn.ModuleList([
            nn.Conv1d(
                in_channels=embedding_dim,
                out_channels=num_filters,
                kernel_size=filter_size
            )
            for filter_size in filter_sizes
        ])

        # Fully connected classification layer
        self.fc = nn.Linear(
            in_features=num_filters * len(filter_sizes),
            out_features=1
        )

        # Sigmoid activation
        self.sigmoid = nn.Sigmoid()


    def forward(self, x):

        # Convert token IDs into embeddings
        x = self.embedding(x)

        # Rearrange dimensions for Conv1d
        x = x.permute(0, 2, 1)

        # Apply convolution + ReLU + max pooling
        pooled_outputs = []

        for conv in self.convs:

            feature_map = torch.relu(conv(x))

            pooled = torch.max(
                feature_map,
                dim=2
            ).values

            pooled_outputs.append(pooled)

        # Concatenate pooled features
        x = torch.cat(
            pooled_outputs,
            dim=1
        )

        # Classification
        x = self.fc(x)

        # Convert logits to probability
        x = self.sigmoid(x)

        return x
```

The model contains:

* an embedding layer,
* multiple convolutional layers,
* ReLU activation,
* max pooling,
* feature concatenation,
* a fully connected layer,
* and a Sigmoid activation.


## 4.2 Understanding the TextCNN Parameters

Suppose we use:

```python
vocab_size = len(vocab)

embedding_dim = 128

num_filters = 64

filter_sizes = [2, 3, 4]
```

Each parameter has a specific role.

### `embedding_dim`

```python
embedding_dim = 128
```

This determines the size of each word embedding.

Each token is represented by:

```text
128 values
```

### `num_filters`

```python
num_filters = 64
```

This determines the number of filters used for each kernel size.

For example:

```text
64 filters with size 2
64 filters with size 3
64 filters with size 4
```

Therefore, the model learns:

```text
64 different 2-word patterns
64 different 3-word patterns
64 different 4-word patterns
```


### `filter_sizes`

```python
filter_sizes = [2, 3, 4]
```

These are the kernel sizes used by the convolutional layers.

They determine how many neighboring words each filter examines.

```text
2 → two neighboring words

3 → three neighboring words

4 → four neighboring words
```

Using multiple filter sizes allows the model to learn patterns of different lengths.


## 4.3 Understanding the Convolution Input

After the embedding layer:

```python
x = self.embedding(x)
```

the shape is:

```text
(batch_size, sequence_length, embedding_dim)
```

For example:

```text
(32, 30, 128)
```

We then use:

```python
x = x.permute(0, 2, 1)
```

The shape becomes:

```text
(32, 128, 30)
```

This corresponds to:

```text
batch_size    = 32
channels      = 128
sequence      = 30
```

For `Conv1d`:

```python
nn.Conv1d(
    in_channels=128,
    out_channels=64,
    kernel_size=3
)
```

the 128 embedding dimensions are treated as the input channels, while the convolution moves across the sequence dimension.

## 4.4 Understanding Feature Maps

Suppose:

```python
sequence_length = 30
filter_size = 3
```

The convolution examines three neighboring positions at a time.

Without padding, the resulting sequence length is:

[
30-3+1=28
]

Therefore, if:

```python
num_filters = 64
```

the feature map has shape:

```text
(batch_size, 64, 28)
```

For a batch of 32 messages:

```text
(32, 64, 28)
```

Each of the 64 filters produces one feature map.

## 4.5 Max Pooling

After applying the convolution and ReLU:

```python
feature_map = torch.relu(conv(x))
```

we perform max pooling:

```python
pooled = torch.max(
    feature_map,
    dim=2
).values
```

The feature map has shape:

```text
(batch_size, num_filters, sequence_length_after_conv)
```

For example:

```text
(32, 64, 28)
```

Max pooling over dimension 2 produces:

```text
(32, 64)
```

Thus, each filter produces a single maximum activation.

Conceptually:

```text
Feature Map

[0.1, 0.4, 0.2, 1.7, 0.3, ...]

              ↓
          Max Pooling
              ↓
             1.7
```

This means that the model keeps the strongest occurrence of the feature detected by each filter.

## 4.6 Combining Different Filter Sizes

Suppose we use:

```python
filter_sizes = [2, 3, 4]
```

and:

```python
num_filters = 64
```

Then the pooled outputs have the following shapes:

```text
Conv-2 → (32, 64)

Conv-3 → (32, 64)

Conv-4 → (32, 64)
```

We concatenate them:

```python
x = torch.cat(
    pooled_outputs,
    dim=1
)
```

The resulting shape becomes:

```text
(32, 192)
```

because:

[
64 + 64 + 64 = 192
]

Therefore, the fully connected layer must accept 192 input features:

```python
self.fc = nn.Linear(
    in_features=192,
    out_features=1
)
```

More generally:

$[
\text{in_features}

\text{num_filters}
\times
\text{number of filter sizes}
]$


## 5. Creating the TextCNN Model

We can now create the TextCNN model:

```python

```

The resulting architecture can be summarized as:

```text

                (32, 30)

                (32, 30, 128)
                      ↓
                Permute
                (32, 128, 30)
                      │
      ├───────────────────────────────┐
      ↓               ↓               ↓
   Conv-2          Conv-3          Conv-4
      ↓               ↓               ↓
   ReLU             ReLU            ReLU
      ↓               ↓               ↓

      ↓               ↓               ↓

                      ↓

```

# 10. Comparing TextCNN with RNN-Based Models

At this point, we have implemented several different neural network architectures for SMS spam classification.

The models introduced throughout the previous sections can be summarized as follows:

| Model       | Main Idea                               | Memory              | Main Strength                  |
| ----------- | --------------------------------------- | ------------------- | ------------------------------ |
| **FFNN**    | Processes pooled word embeddings        | No                  | Simple baseline                |
| **RNN**     | Sequential hidden state                 | Hidden state        | Sequential processing          |
| **LSTM**    | Gated recurrent architecture            | Cell + hidden state | Long-term dependencies         |
| **GRU**     | Simplified gated recurrent architecture | Hidden state        | Efficient recurrent processing |
| **TextCNN** | Convolutional local feature extraction  | No recurrent memory | Fast local pattern detection   |

The main conceptual difference is that RNN-based models process the sequence recurrently:

```text
Word 1
  ↓
Word 2
  ↓
Word 3
  ↓
...
Word 30
```

whereas TextCNN processes multiple neighboring words simultaneously:

```text
Word 1 ─┐
Word 2 ─┼─► Filter
Word 3 ─┘

Word 2 ─┐
Word 3 ─┼─► Filter
Word 4 ─┘

Word 3 ─┐
Word 4 ─┼─► Filter
Word 5 ─┘
```

This makes CNNs particularly effective at detecting local patterns such as phrases and short word combinations.

# 11. Advantages and Limitations of TextCNNs

TextCNNs have several important advantages for text classification.

### Advantages

**1. Efficient computation**

Unlike RNNs, CNNs do not need to process the sequence strictly one time step after another. Multiple positions can be processed in parallel.

**2. Effective local pattern detection**

Convolutional filters are very effective at detecting short phrases and local word combinations.

**3. Multiple pattern lengths**

Using different kernel sizes allows the model to detect patterns of different lengths.

For example:

```text
kernel size 2 → short patterns
kernel size 3 → medium patterns
kernel size 4 → longer patterns
```

**4. Simpler architecture**

Compared with LSTMs, TextCNNs do not require hidden states, cell states, or recurrent gating mechanisms.

### Limitations

However, TextCNNs also have limitations.

**1. Limited long-range dependency modeling**

A convolutional filter primarily examines a local region of the sequence. Therefore, capturing relationships between words that are very far apart can be difficult.

**2. No explicit sequential memory**

Unlike RNN, LSTM, and GRU models, a basic TextCNN does not maintain a recurrent memory of previous words.

**3. Dependence on kernel sizes**

The model's ability to detect patterns depends on the selected filter sizes.

For example:

```python
filter_sizes = [2, 3, 4]
```

may work well for one dataset but not necessarily for another.
