# 1. Feed-Forward Neural Network for Text Classification

In the previous sections, we loaded the SMS Spam Collection dataset, split it into training and test sets, tokenized the text, and transformed each word into a dense vector using an embedding layer. At this stage, every SMS message is represented as a sequence of word embeddings and is ready to be processed by a neural network.

In this section, we will implement our first text classification model using a **Feed-Forward Neural Network (FFNN)**. Although this architecture does not explicitly model the sequential nature of language, it provides a simple and effective baseline for understanding the complete text classification pipeline. In the following chapters, we will replace this baseline with more advanced architectures such as **RNNs**, **LSTMs**, **GRUs**, and **CNNs for text classification**, allowing us to compare their performance on the same dataset.

The overall workflow is illustrated below.

```text
SMS Message
      ↓
Tokenization
      ↓
Token IDs
      ↓
Embedding Layer
      ↓
Average Pooling
      ↓
Feed-Forward Neural Network
      ↓
Spam / Ham Prediction
```


## 1.1 Building the Model

After the embedding layer, each SMS message is represented as a matrix of shape

```text
(sequence_length, embedding_dimension)
```

For example,

```text
(30, 128)
```

where each row corresponds to the embedding vector of one word.

A feed-forward neural network, however, expects a **single feature vector** for each input sample rather than a sequence of vectors. Therefore, before passing the data to the classifier, we compute the average of all word embeddings.

This operation is known as **average pooling** and produces a fixed-length representation of the entire sentence.

The classifier itself consists of two fully connected layers separated by a ReLU activation function. The final Sigmoid activation produces a probability between **0** and **1**, representing the likelihood that the SMS message is spam.

The complete implementation is shown below.

```python
import torch
import torch.nn as nn

class FeedForwardClassifier(nn.Module):

    def __init__(self, vocab_size, embedding_dim, hidden_dim):

        super().__init__()

        # Word embedding layer
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )

        # Feed-forward classifier
        self.classifier = nn.Sequential(
            nn.Linear(embedding_dim, hidden_dim),
            nn.ReLU(),
            nn.Linear(hidden_dim, 1),
            nn.Sigmoid()
        )

    def forward(self, x):

        # Convert token IDs to word embeddings
        x = self.embedding(x)

        # Average the embeddings across the sequence dimension
        x = x.mean(dim=1)

        # Classification
        x = self.classifier(x)

        return x
```

Next, we create an instance of the model.

```python
vocab_size = len(vocab)
embedding_dim = 128
hidden_dim = 64

model = FeedForwardClassifier(
    vocab_size=vocab_size,
    embedding_dim=embedding_dim,
    hidden_dim=hidden_dim
)

print(model)
```


## 1.2 Understanding the Model Architecture

Suppose a mini-batch contains **32** SMS messages, each padded to **30** tokens.

The dimensions of the data change as follows.

| Layer           | Output Shape    |
| --------------- | --------------- |
| Input           | `(32, 30)`      |
| Embedding       | `(32, 30, 128)` |
| Average Pooling | `(32, 128)`     |
| Linear          | `(32, 64)`      |
| ReLU            | `(32, 64)`      |
| Linear          | `(32, 1)`       |
| Sigmoid         | `(32, 1)`       |

The final output is a probability indicating how likely each SMS message is to belong to the **spam** class.


## 1.3 Defining the Loss Function and Optimizer

Training a neural network requires two essential components:

1. **A loss function**, which measures the difference between the predicted probabilities and the true labels.
2. **An optimizer**, which updates the model parameters to minimize the loss.

Since SMS spam detection is a binary classification problem, we use the **Binary Cross-Entropy Loss** together with the **Adam** optimizer.

```python
import torch.optim as optim

criterion = nn.BCELoss()

optimizer = optim.Adam(
    model.parameters(),
    lr=0.001
)
```

The loss function guides the learning process, while the optimizer determines how the model parameters are updated after each training step.


## 1.4 Preparing the Dataset

Before training the model, the tokenized SMS messages must be organized into a format that PyTorch can efficiently process.

We begin by creating a custom dataset class.

Next, we create the training and test datasets.

```python
train_dataset = SMSDataset(train_df)
test_dataset = SMSDataset(test_df)
```

Finally, we create the data loaders.

```python
from torch.utils.data import DataLoader

batch_size = 32

train_loader = DataLoader(
    train_dataset,
    batch_size=batch_size,
    shuffle=True
)

test_loader = DataLoader(
    test_dataset,
    batch_size=batch_size,
    shuffle=False
)
```

The `DataLoader` automatically groups samples into mini-batches and shuffles the training data at the beginning of each epoch.


## 1.5 Training the Model

Training consists of repeatedly presenting mini-batches of SMS messages to the neural network and updating the model parameters using backpropagation.

```python
num_epochs = 10

for epoch in range(num_epochs):

    model.train()

    running_loss = 0.0

    for inputs, labels in train_loader:

        optimizer.zero_grad()

        outputs = model(inputs).squeeze()

        loss = criterion(outputs, labels)

        loss.backward()

        optimizer.step()

        running_loss += loss.item()

    epoch_loss = running_loss / len(train_loader)

    print(
        f"Epoch [{epoch+1}/{num_epochs}] "
        f"Loss: {epoch_loss:.4f}"
    )
```

During each iteration, the model performs the following operations:

1. Receives a mini-batch of SMS messages.
2. Computes the predicted spam probabilities.
3. Calculates the loss.
4. Computes the gradients using backpropagation.
5. Updates the model parameters using the Adam optimizer.

These steps are repeated for every mini-batch until the entire training dataset has been processed. Completing one pass through the full training dataset is called an **epoch**.


## 1.6 Evaluating the Model

After training, we evaluate the classifier using the test dataset. During evaluation, gradients are not required, making the process both faster and more memory-efficient.

```python
model.eval()

correct = 0
total = 0

with torch.no_grad():

    for inputs, labels in test_loader:

        outputs = model(inputs).squeeze()

        predictions = (outputs >= 0.5).float()

        total += labels.size(0)

        correct += (predictions == labels).sum().item()

accuracy = correct / total

print(f"Test Accuracy: {accuracy:.4f}")
```

The model produces a probability for each SMS message. A threshold of **0.5** is used to assign class labels:

* Probability **≥ 0.5** → **Spam (1)**
* Probability **< 0.5** → **Ham (0)**

The final classification accuracy is computed as

[
\text{Accuracy} =
\frac{\text{Number of Correct Predictions}}
{\text{Total Number of Samples}}
]

which measures the proportion of correctly classified messages in the test dataset.

# Summary

In this section, we implemented our first neural network for text classification using a **Feed-Forward Neural Network**. Starting from tokenized SMS messages, we transformed word indices into dense embeddings, summarized each message using average pooling, and classified it using a small fully connected neural network.

Although this model provides a simple and effective baseline, it has an important limitation: the average pooling operation ignores the order of words in a sentence. As a result, it cannot capture sequential dependencies or contextual information that are essential for understanding natural language.

In the next section, we will introduce the **Recurrent Neural Network (RNN)**, which processes text one word at a time and maintains a hidden state that allows it to model sequential information. This will enable the network to learn contextual relationships between words that a feed-forward architecture cannot capture.
