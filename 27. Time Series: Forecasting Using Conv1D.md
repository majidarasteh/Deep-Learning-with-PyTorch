
# 1. Time-Series Forecasting Using Conv1D

A **One-Dimensional Convolutional Neural Network (Conv1D)** can be used for time-series forecasting.

Unlike RNN, LSTM, and GRU, a Conv1D does not process the sequence one time step at a time. Instead, it uses **convolutional filters** to detect local patterns in the time series.

For example, consider the following Bitcoin closing prices:

```text
[95000, 96200, 94800, 97100, 98000, 97500, 98900]
```

A Conv1D can examine consecutive groups of observations and learn local patterns such as:

```text
[95000, 96200, 94800]
```

then:

```text
[96200, 94800, 97100]
```

and so on.

The important idea is:

> **Conv1D learns local temporal patterns and features from neighboring observations in a time series.**


## 1.1 Basic Idea of Conv1D

In a Conv1D model, a **kernel** (or filter) moves across the time dimension.

For example, if the kernel size is `5`, the convolution examines five consecutive observations at a time:

```text
[Price₁, Price₂, Price₃, Price₄, Price₅]
```

then:

```text
[Price₂, Price₃, Price₄, Price₅, Price₆]
```

and continues moving across the sequence.

The filter learns to detect useful local patterns in these observations.

Unlike an RNN, a Conv1D does not maintain a hidden state.

Unlike an LSTM, it does not maintain a hidden state and cell state.

Instead, it learns temporal patterns through convolutional filters.


## 1.2 Conv1D Filters and `out_channels`

An important parameter in `Conv1D` is:

```python
out_channels
```

The `out_channels` parameter specifies **how many convolutional filters the layer contains**.

For example:

```python
nn.Conv1d(
    in_channels=1,
    out_channels=128,
    kernel_size=5
)
```

means that the layer uses **128 different filters**.

Each filter can learn to detect a different pattern in the time series.

Conceptually:

```text
Input Time Series
       │
       ├── Filter 1  → Feature Map 1
       ├── Filter 2  → Feature Map 2
       ├── Filter 3  → Feature Map 3
       │
       │       ...
       │
       └── Filter 128 → Feature Map 128
```

Therefore:

```text
out_channels = 128
```

means that the Conv1D layer produces **128 feature maps**.

The first Conv1D layer in our model uses:

```python
in_channels=1
out_channels=128
```

because our input contains one feature:

```text
Close Price
```

and we want the layer to learn 128 different temporal features.

## 1.3 Input Shape for Conv1D

PyTorch's `nn.Conv1d` expects the input in the following format:

```text
(batch_size, channels, sequence_length)
```

For our univariate time series:

```text
(batch_size, 1, window_size)
```

For example:

```text
(64, 1, 60)
```

where:

```text
64 → number of sequences in the batch
1  → number of input features/channels
60 → number of time steps
```

This is different from RNN, LSTM, and GRU.

RNN/LSTM/GRU use:

```text
(batch_size, window_size, feature_size)
```

For example:

```text
(64, 60, 1)
```

Conv1D uses:

```text
(batch_size, feature_size, window_size)
```

For example:

```text
(64, 1, 60)
```

## 1.4 Conv1D Architecture

We can stack multiple Conv1D layers to allow the model to learn more complex patterns.

Our model uses two Conv1D layers.

The first Conv1D layer learns low-level local patterns.

The second Conv1D layer receives these learned features and can learn more complex patterns from them.

For our time-series forecasting problem, the overall architecture is:

```text
Input
(batch_size, 1, window_size)
            │
            ▼
          Conv1D
        1 → 128
            │
            ▼
           ReLU
            │
            ▼
          Conv1D
        128 → 128
            │
            ▼
           ReLU
            │
            ▼
         Flatten
            │
            ▼
       Linear Layer
            │
            ▼
      Predicted Price
```

For our current configuration:

```text
Input
(64, 1, 60)
    │
    ▼
Conv1D
1 → 128
    │
    ▼
ReLU
    │
    ▼
Conv1D
128 → 128
    │
    ▼
ReLU
    │
    ▼
Flatten
    │
    ▼
Linear
6656 → 1
    │
    ▼
Prediction
(64, 1)
```

The main concepts are:

1. Conv1D can be used for time-series forecasting.
2. Conv1D learns local temporal patterns.
3. `kernel_size` determines how many consecutive time steps each filter examines.
4. `out_channels` determines the number of filters and feature maps.
5. Multiple Conv1D layers can learn increasingly complex features.
6. Conv1D does not use a hidden state or cell state.
7. The input shape is:

```text
(batch_size, feature_size, window_size)
```

# 2. Creating the Conv1D Model

We can implement the model using PyTorch.

```python
import torch
import torch.nn as nn
```

The model is:

```python
class Conv1DModel(nn.Module):

    def __init__(
        self,
        feature_size=1,
        window_size=60,
        horizon=1,
        out_channels=128,
        kernel_size=5
    ):
        super().__init__()

        # First Conv1D layer
        self.conv1 = nn.Conv1d(
            in_channels=feature_size,
            out_channels=out_channels,
            kernel_size=kernel_size,
        )

        # Second Conv1D layer
        self.conv2 = nn.Conv1d(
            in_channels=out_channels,
            out_channels=out_channels,
            kernel_size=kernel_size,
        )

        self.relu = nn.ReLU()

        # Calculate the output size after two Conv1D layers
        conv_output_size = window_size - 2 * (kernel_size - 1)

        self.fc = nn.Linear(
            out_channels * conv_output_size,
            horizon
        )


    def forward(self, x):

        # First Conv1D
        output = self.conv1(x)

        # ReLU activation
        output = self.relu(output)

        # Second Conv1D
        output = self.conv2(output)

        # ReLU activation
        output = self.relu(output)

        # Flatten
        output = output.reshape(
            output.size(0),
            -1
        )

        # Output layer
        output = self.fc(output)

        return output
```


### `feature_size`

We use:

```python
feature_size = 1
```

because our dataset contains only one feature:

```text
Close Price
```

Therefore, the first Conv1D layer has:

```python
in_channels=feature_size
```

which means:

```text
in_channels = 1
```

### `out_channels`

We use:

```python
out_channels = 128
```

This means that the Conv1D layer contains **128 filters**.

Each filter can learn a different temporal pattern.

Therefore, the first Conv1D transforms:

```text
1 input channel
```

into:

```text
128 output channels
```

For the second Conv1D layer:

```python
self.conv2 = nn.Conv1d(
    in_channels=out_channels,
    out_channels=out_channels,
    kernel_size=kernel_size
)
```

we have:

```text
in_channels = 128
out_channels = 128
```

Therefore, the second Conv1D receives the 128 feature maps produced by the first Conv1D and produces another 128 feature maps.

```text
Conv1D #1
1 → 128
     ↓
Conv1D #2
128 → 128
```

### `kernel_size`

We use:

```python
kernel_size = 5
```

This means that each convolutional filter examines five consecutive time steps.

For example:

```text
[Price₁, Price₂, Price₃, Price₄, Price₅]
```

The filter then moves one step forward:

```text
[Price₂, Price₃, Price₄, Price₅, Price₆]
```

and so on.


### Output Size of Conv1D

Our input window contains:

```text
window_size = 60
```

and the kernel size is:

```text
kernel_size = 5
```

We use the default:

```text
stride = 1
padding = 0
```

For the first Conv1D, the output sequence length is:

```text
60 - 5 + 1 = 56
```

Therefore:

```text
Input
(64, 1, 60)

       ↓

Conv1D

       ↓

(64, 128, 56)
```

The second Conv1D operates on this output:

```text
(64, 128, 56)
```

Its output sequence length is:

```text
56 - 5 + 1 = 52
```

Therefore:

```text
(64, 128, 56)

       ↓

Conv1D

       ↓

(64, 128, 52)
```

After flattening:

```text
128 × 52 = 6656
```

Therefore, the final linear layer is:

```text
6656 → 1
```

## 2.1 Why Do We Use `ReLU`?

Unlike our RNN, LSTM, and GRU models, we explicitly use `ReLU` after each Conv1D layer:

```python
self.relu = nn.ReLU()
```

The architecture is:

```text
Conv1D
   ↓
ReLU
   ↓
Conv1D
   ↓
ReLU
   ↓
Flatten
   ↓
Linear
   ↓
Prediction
```

ReLU introduces a nonlinear transformation after each convolutional layer.

The ReLU function is:

$$
ReLU(x)=\max(0,x)
$$

Therefore:

```text
negative value → 0
positive value → unchanged
```

The final linear layer does not use ReLU because this is a regression problem and we want the model to produce a continuous price.


# 3. Preparing Data for Conv1D

Our existing `create_sliding_windows()` function can still be used.

For example:

```python
window_size = 60
horizon = 1
```

We can create the sliding windows:

```python
X_train, y_train = create_sliding_windows(
    train_values,
    window_size=window_size,
    horizon=horizon
)

X_test, y_test = create_sliding_windows(
    test_values,
    window_size=window_size,
    horizon=horizon
)
```

The sliding-window function produces:

```text
X_train
    ↓
(number_of_samples, 60)

y_train
    ↓
(number_of_samples, 1)
```

However, Conv1D requires:

```text
(number_of_samples, 1, 60)
```

Therefore, we need to add the feature/channel dimension.

We can use:

```python
X_train = X_train.reshape(X_train.shape[0],1,  X_train.shape[1])
```

Similarly:

```python
X_test = X_test.reshape(X_test.shape[0], 1, X_test.shape[1])
```

Now:

```text
Before:

X_train
(samples, 60)


After:

X_train
(samples, 1, 60)
```

## 4.1 Loss Function

As in our FFNN, RNN, LSTM, and GRU models, we use **Mean Absolute Error (MAE)**.

In PyTorch:

```python
criterion = nn.L1Loss()
```

MAE measures the average absolute difference between the actual and predicted prices.


## 4.2 Adam Optimizer

We use the **Adam optimizer**:

```python
optimizer = torch.optim.Adam(
    model_Conv1D.parameters(),
    lr=0.001
)
```

Adam updates the Conv1D model's parameters during training based on the gradients calculated during backpropagation.


## 4.3 Training the Conv1D

Because we already created a general `train_model()` function, we do not need to write another training loop specifically for Conv1D.


## 4.6 Predicting the Next Bitcoin Price

Our RNN, LSTM, and GRU models require the input shape:

```text
(1, window_size, 1)
```

However, Conv1D requires:

```text
(1, 1, window_size)
```

Therefore, we use a Conv1D-specific prediction function:

```python
def predict_next_price_Conv1D(model, data, window_size):

    # Set model to evaluation mode
    model.eval()

    # Get the latest window
    input_data = data[-window_size:]

    # Convert to NumPy
    input_data = np.asarray(input_data, dtype=np.float32)

    # Convert to tensor
    input_tensor = torch.tensor(input_data, dtype=torch.float32)

    # Reshape:
    # (window_size)
    #       ↓
    # (1, 1, window_size)
    input_tensor = input_tensor.reshape(1, 1,  window_size)

    # Move to device
    input_tensor = input_tensor.to(device)

    # Make prediction
    with torch.no_grad():
        prediction = model(input_tensor)

    # Return a single value
    return prediction.squeeze()
```

We can then predict the next Bitcoin closing price:

```python
next_price_Conv1D = predict_next_price_Conv1D(
    model=model_Conv1D,
    data=df["Close"],
    window_size=window_size
)

print(
    f"Predicted next Bitcoin closing price: "
    f"${next_price_Conv1D:}"
)
```
