# 1. What Is NLP — Precisely?

Natural Language Processing (NLP) is the study of how to make computers process and understand **sequential symbolic data** (language).

Language is:

* Discrete (words are symbols)
* Sequential (order matters)
* Context-dependent (meaning depends on nearby words)

Unlike images (which are continuous numeric grids), text is made of symbols like:

```
["earthquake", "destroyed", "city"]
```

Neural networks require **numbers**, not symbols.
So NLP is fundamentally about solving this problem:

> How do we convert sequences of symbols into meaningful numerical representations?

---

## Why Order Matters (Numerical Illustration)

Consider two sentences:

1. "Dog bites man"
2. "Man bites dog"

If we ignore order and just count words:

Vocabulary = {dog, bites, man}

Bag-of-words representation:

Sentence 1 → [1,1,1]
Sentence 2 → [1,1,1]

They look identical.

But meaning is completely different.

Therefore:

Language ≠ unordered set
Language = ordered sequence

This is why sequence models (like RNNs) are important.

---

# 2. The Dataset — What Are We Really Modeling?

We are solving **binary classification**.

Given:

**x = tweet text**

Predict:

$y\in {0 | 1}$

Example:

| Tweet                         | Label |
| ----------------------------- | ----- |
| "Earthquake destroyed houses" | 1     |
| "I love pizza"                | 0     |

Formally, the model learns a function:

$f(x) \rightarrow P(y=1|x)$

So the output is a probability between 0 and 1.

---

## Why Train / Validation Split?

We split:

* 90% training
* 10% validation

Why?

Because if we train and test on the same data, the model may memorize.

Example:

Suppose model sees:

"Fire in building" → Disaster

If we test on the same sentence, accuracy = 100%.
But this tells us nothing about generalization.

Validation data simulates **new unseen data**.

---

# 3. Building the Vocabulary

Before converting words into numbers, we first need to decide **which words the model knows**. The collection of all known tokens is called the **vocabulary**. Suppose our corpus contains

```text
I love NLP
I love Python
Python is amazing
```

The vocabulary becomes

```text
{
PAD,
UNK,
I,
love,
NLP,
Python,
is,
amazing
}
```

We then assign an integer ID to every token.

```text
PAD = 0
UNK = 1
I = 2
love = 3
NLP = 4
Python = 5
is = 6
amazing = 7
```

Notice that these numbers are **not meaningful**. They are simply addresses that identify words.

---


# 4. Tokenization — Converting Language to Integers

Neural networks operate on numbers.

We must map each token (word/character/subword) to an integer.

---

## 4.1 Word-Level Tokenization (Detailed)

Suppose our training data contains:

```
"I love python"
"I love deep learning"
```

Step 1: Build vocabulary.

Unique words:

```
["I", "love", "python", "deep", "learning"]
```

Assign integer IDs:

```
I → 1
love → 2
python → 3
deep → 4
learning → 5
```

(0 is usually reserved for padding)

Now:

"I love python" → [1,2,3]

"I love deep learning" → [1,2,4,5]

---

## What If Vocabulary Is Large?

In real datasets:

* Vocabulary may be 20,000+ words.
* Many rare words exist.

So we define:

```
max_vocab_size = 10,000
```

Keep only most frequent 10,000 words.

All others → mapped to special token:

```
[UNK] (Unknown)
```

Example:

If "tsunamiwave" appears once and is outside top 10k:

"tsunamiwave destroyed city"

→ [UNK, id_destroyed, id_city]

---

## 4.2 Sequence Length and Padding

Neural networks require fixed-size inputs.

Example:

Sentence A: [1,2,3]
Sentence B: [1,2,4,5]

Different lengths (3 vs 4).

We fix:

```
max_length = 5
```

Padding with zeros. 

Sentence A → [1,2,3,0,0]
Sentence B → [1,2,4,5,0]

Now both have length 5.

---

## Why Padding Uses 0?

Because:

0 = reserved padding token
It does not represent a real word.

---

## Truncation

What if a sentence is longer than the maximum length?

Suppose

```
max_length = 5
```

Sentence

```text
I really really really really really love NLP
```

becomes

```text
I really really really really
```

The remaining words are discarded. This process is called **truncation**.

## 4.3 Character-Level Tokenization

Instead of words:

"cat" → ['c','a','t']

Suppose:

```
a → 1
b → 2
c → 3
...
```

"cat" → [3,1,20]

Pros:

* Very small vocabulary (~30–100)

Cons:

* Sequences become long.
* Harder to learn long dependencies.

---

## 4.4 Subword Tokenization

Balances word and character level.

Example:

"unhappiness"

Split into:

["un", "happy", "ness"]

Better handling of rare words.

Used in modern large language models.

---

# 5. Embedding — Turning Integers Into Meaning

After tokenization:

Sentence:

[1, 2, 3, 0, 0]

These numbers have no meaning yet.

If:

python = 3
earthquake = 17

There is no mathematical relationship between 3 and 17.

We need semantic structure.

---

## 5.1 What Is an Embedding?

Embedding = a lookup table:

$E \in \mathbb{R}^{V \times d}$

Where:

* ( V ) = vocabulary size
* ( d ) = embedding dimension

Example:

$V = 5$ and $d = 3$

Embedding matrix:

```
[0.1  0.3  0.5 
 0.7  0.2  0.9 
 0.4  0.8  0.6 
 0.9  0.1  0.2 
 0.3  0.7  0.4]
```

Each row corresponds to one word.

If:

"python" = index 3

Then embedding("python") = row 3:

```
[0.4, 0.8, 0.6]
```

---

## 5.2 Numerical Example of Forward Pass

Suppose sentence:

[2,3]

Embedding dimension = 3

Embedding matrix:

```
2 → [0.7, 0.2, 0.9]
3 → [0.4, 0.8, 0.6]
```

Embedded sentence becomes:

```
[0.7  0.2  0.9 
 0.4  0.8  0.6]
```

Shape:

(sequence_length, embedding_dim) = (2, 3)

---

## 5.3 Why Embeddings Work

**During training:**

* Backpropagation updates embedding vectors.
* Words that appear in similar contexts move closer in vector space.

Example (after training):

* distance("earthquake", "flood") → small
* distance("earthquake", "pizza") → large

So embedding captures semantic similarity.

---

## 5.4 Understanding Shape Transformations

If:

* Batch size = 32
* Sequence length = 15
* Embedding dim = 128

Input shape: $(32, 15)$

After embedding: $(32, 15, 128)$

Each word now has a **128-dimensional** vector.

---

## 5.5 PyTorch Example (Conceptual)

```python
import torch.nn as nn

vocab_size = 10000
embedding_dim = 128

embedding = nn.Embedding(vocab_size, embedding_dim)

# Suppose input batch:
# shape: (32, 15)
embedded = embedding(input_tokens)

# Output shape:
# (32, 15, 128)
```

The embedding layer is just a learnable matrix lookup.

---

# Key Conceptual Understanding

* Tokenization: Maps symbols → integers **(no meaning yet)**
* Embedding: Maps integers → dense vectors **(learned semantic meaning)**

So the full transformation is:

**Text**
→ Tokens (IDs)
→ Vectors
→ Neural network
