# 1. Gated Recurrent Units (GRUs) for Text Classification

A GRU is a gated recurrent neural network architecture designed to capture short-term and long-term dependencies while using a simpler structure than an LSTM. Instead of maintaining both a hidden state and a separate cell state, a GRU uses a **single hidden state** to store and propagate information through the sequence.

A GRU uses two main gates:

* **Update Gate** – determines how much of the previous hidden state should be retained and how much new information should be incorporated.
* **Reset Gate** – determines how much of the previous hidden state should be considered when generating new information.

These gates allow the GRU to control the flow of information and reduce the difficulty of learning long-term dependencies.

## 1.1 From RNNs to GRUs

In the previous lectures, we saw that vanilla RNNs can process sequential data by maintaining a hidden state.

At each time step, a vanilla RNN computes a new hidden state from:

```text
Current Input
      +
Previous Hidden State
      ↓
    RNN Cell
      ↓
New Hidden State
```

Although this mechanism allows an RNN to remember previous information, it becomes increasingly difficult to preserve useful information over long sequences.

The main reason is the **vanishing gradient problem**.

During backpropagation through time, gradients are repeatedly propagated through the recurrent network. When the sequence becomes long, these gradients may become extremely small.

Consequently, the model may have difficulty learning relationships such as:

```text
Word 1 ─────────────────────────────► Word 30
```

when the information at Word 1 is important for interpreting Word 30.

LSTM networks address this problem by introducing a separate cell state and three gates.

GRUs take a different approach.

Instead of introducing a separate cell state, GRUs use a **single hidden state with two gates**.

Therefore, the basic idea can be summarized as:

```text
Vanilla RNN
    ↓
Single Hidden State
    ↓
Difficulty with Long-Term Dependencies


LSTM
    ↓
Hidden State + Cell State
    ↓
Three Gates


GRU
    ↓
Single Hidden State
    ↓
Two Gates
```

The architectures can be summarized as follows:


| Model    | Memory Representation | Gates | Separate Cell State | Complexity |
| -------- | --------------------- | ----: | ------------------: | ---------- |
| **RNN**  | Hidden state          |  None |                  No | Low        |
| **LSTM** | Hidden + Cell state   |     3 |                 Yes | Higher     |
| **GRU**  | Hidden state          |     2 |                  No | Medium     |

* The vanilla RNN has the simplest architecture but has difficulty learning long-term dependencies.
* The LSTM introduces a separate cell state and three gates, providing a sophisticated mechanism for controlling long-term memory.
* The GRU simplifies the LSTM architecture by combining its memory mechanisms into a single hidden state and using only two gates. This simpler architecture allows GRUs to model long-term dependencies while using fewer components than LSTMs.

A **Gated Recurrent Unit (GRU)** is a recurrent neural network architecture that uses gating mechanisms to control how information flows through the network.

Like a vanilla RNN, a GRU processes a sequence one element at a time.

For a text sequence:

```text
x₁, x₂, x₃, ..., xₜ
```

the GRU produces a sequence of hidden states:

```text
h₁, h₂, h₃, ..., hₜ
```

However, unlike a vanilla RNN, the GRU does not simply replace the previous hidden state with a new hidden state.

Instead, it learns how much of the previous information should be retained and how much new information should be incorporated.

The gates inside the GRU determine how the previous hidden state and current input should be combined.

## 1.2 Hidden State, Gate, and candidate hidden state in a GRU

Unlike an LSTM, a GRU does **not** maintain a separate cell state.

A GRU uses only one state:

```text
Hidden State (hₜ)
```
This is one of the most important differences between GRUs and LSTMs.

In an LSTM: `Hidden State + Cell State` are maintained separately.

In a GRU: `Hidden State` acts as the only recurrent memory.

A simple RNN always updates its hidden state using the current input and previous hidden state.

A GRU introduces gates to make this process more selective. The GRU can learn:

> "How much of the previous information should I keep?"

and:

> "How much should I use the previous state when processing this new input?"

This gives the network greater control over its memory. A GRU contains two main gates:

1. **Update Gate**
2. **Reset Gate**

These gates are implemented using sigmoid functions, so their values range between 0 and 1.

Conceptually:

```text
                 Current Input
                      │
                      ▼
              ┌───────────────┐
              │               │
Previous ───► │     GRU       │ ───► New Hidden State
Hidden State  │               │
              └───────────────┘
                 ▲       ▲
                 │       │
             Reset      Update
              Gate       Gate
```

Each gate has a different role.

* The **update gate** determines how much information from the previous hidden state should be retained and how much new information should be incorporated.
* The **reset gate** controls how much of the previous hidden state should be used when generating the candidate hidden state.

The roles of the two gates are:

| Component        | Main Function                                                                           |
| ---------------- | --------------------------------------------------------------------------------------- |
| **Reset Gate**   | Controls how much previous information is used when creating the candidate hidden state |
| **Update Gate**  | Controls how much new information is incorporated into the hidden state                 |
| **Hidden State** | Stores and carries information through the sequence                                     |


# 2. Implementing a GRU-Based Text Classification Model Using PyTorch

We can now implement a GRU-based SMS classification model using PyTorch.

The overall architecture is:

```text
SMS Text
   ↓
Tokenization
   ↓
Token IDs
   ↓
Embedding Layer
   ↓
GRU
   ↓
Final Hidden State
   ↓
Fully Connected Layer
   ↓
Sigmoid
   ↓
Spam / Ham
```

The model is very similar to the RNN and LSTM classifiers implemented in the previous sections.

The main difference is the recurrent layer:

```python
nn.GRU
```

instead of:

```python
nn.RNN
```

or:

```python
nn.LSTM
```

## 2.1 Creating the GRU Model

The PyTorch implementation is:

```python
import torch
import torch.nn as nn


class GRUClassifier(nn.Module):

    def __init__(
        self,
        vocab_size,
        embedding_dim,
        hidden_dim
    ):

        super().__init__()

        # Word embedding layer
        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )

        # GRU layer
        self.gru = nn.GRU(
            input_size=embedding_dim,
            hidden_size=hidden_dim,
            num_layers=1,       # Number of GRU layers
            batch_first=True
        )

        # Fully connected output layer
        self.fc = nn.Linear(
            in_features=hidden_dim,
            out_features=1
        )

        # Sigmoid activation
        self.sigmoid = nn.Sigmoid()


    def forward(self, x):

        # Convert token IDs into embeddings
        x = self.embedding(x)

        # Process the sequence using GRU
        output, hidden = self.gru(x)

        # Use the final hidden state
        hidden = hidden[-1]

        # Fully connected layer
        output = self.fc(hidden)

        # Convert output to probability
        output = self.sigmoid(output)

        return output
```

The parameter: `num_layers=1` specifies the **number of GRU layers** in the network. In this case, the model contains **one GRU layer**.

### 2.1.1 Understanding the Embedding Layer

The input to the model consists of token IDs.

For example:

```text
[324, 12, 48, 97, 5, 221, 0, ...]
```

The embedding layer converts these integer IDs into dense vectors.

If:

```python
embedding_dim = 128
```

then every token is represented by a 128-dimensional vector.

For one SMS message:

```text
(30)
```

becomes:

```text
(30, 128)
```

For a batch of 32 SMS messages:

```text
(32, 30)
```

becomes:

```text
(32, 30, 128)
```

Therefore:

```text
Token IDs
(32, 30)

      ↓

Embedding

      ↓

Word Embeddings
(32, 30, 128)
```

The sequence of word embeddings is then passed to the GRU.

### 2.1.2 Understanding the GRU Layer

The GRU layer is defined as:

```python
self.gru = nn.GRU(
    input_size=embedding_dim,
    hidden_size=hidden_dim,
    num_layers=1,
    batch_first=True
)
```

The GRU receives a sequence of word embeddings and processes them sequentially.

For example:

```text
x₁ → GRU → h₁
x₂ → GRU → h₂
x₃ → GRU → h₃
...
x₃₀ → GRU → h₃₀
```

At every time step, the GRU uses:

```text
Current Input
+
Previous Hidden State
```

to calculate the new hidden state.

Unlike an LSTM, the GRU does not return a separate cell state.

Therefore:

```python
output, hidden = self.gru(x)
```

returns only:

```text
output
hidden
```

rather than:

```text
output
hidden
cell
```

as in the LSTM model.

### 2.1.3 Understanding the GRU Outputs

For:

```python
batch_size = 32
sequence_length = 30
hidden_dim = 64
```

the GRU produces:

```text
output → (32, 30, 64)

hidden → (1, 32, 64)
```

The `output` tensor contains the hidden state produced at every time step:

```text
h₁, h₂, h₃, ..., h₃₀
```

for every SMS message.

The `hidden` tensor contains the final hidden state for each GRU layer.

Because our model contains one GRU layer:

```text
hidden.shape

(1, 32, 64)
```

The first dimension represents the number of GRU layers.

We use:

```python
hidden = hidden[-1]
```

to select the final hidden state of the last GRU layer.

Its shape becomes:

```text
(32, 64)
```

Therefore, each SMS message is represented by one 64-dimensional vector.

### 2.1.4 Why Do We Use the Final Hidden State?

The GRU processes the complete sequence one word at a time:

```text
Word 1
   ↓
h₁

Word 2
   ↓
h₂

Word 3
   ↓
h₃

...

Word 30
   ↓
h₃₀
```

The final hidden state:

```text
h₃₀
```

contains information accumulated while processing the sequence.

Therefore, for text classification, we can use this final hidden state as a fixed-size representation of the complete SMS message.

Conceptually:

```text
SMS Message
     │
     ▼
Word 1 → GRU → h₁
Word 2 → GRU → h₂
Word 3 → GRU → h₃
   ⋮
Word 30 → GRU → h₃₀
                │
                ▼
          Final Hidden State
                │
                ▼
          Classification
```

### 2.1.5 Understanding the Fully Connected Layer

The final hidden state has: `hidden_dim` features. If: `hidden_dim = 64`then:

```text
hidden.shape

(32, 64)
```

The fully connected layer is:

```python
self.fc = nn.Linear(
    in_features=hidden_dim,
    out_features=1
)
```

Therefore:

```text
(32, 64)
      ↓
Linear
      ↓
(32, 1)
```

The value `out_features=1` is used because this is a binary classification problem:

```text
ham  → 0
spam → 1
```

One output value is therefore sufficient to represent the prediction.

### 2.1.6 Understanding the Sigmoid Activation

The fully connected layer produces a logit.

We then apply the Sigmoid activation:

```python
output = self.sigmoid(output)
```

The Sigmoid function converts the logit into a value between 0 and 1.

For example:

```text
0.05 → Ham
0.18 → Ham
0.43 → Ham
0.71 → Spam
0.94 → Spam
```

Using a threshold of 0.5:

```text
Probability ≥ 0.5 → Spam (1)

Probability < 0.5 → Ham (0)
```

## 3. Creating the GRU Model

We can now create an instance of the GRU classifier using the vocabulary and hyperparameters defined in the previous sections.

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print(device)

vocab_size = len(vocab)
embedding_dim = 128
hidden_dim = 64


model_GRU = GRUClassifier(
    vocab_size=vocab_size,
    embedding_dim=embedding_dim,
    hidden_dim=hidden_dim
).to(device)

print(model_GRU)
```

The resulting architecture is conceptually:

```text
Input Token IDs
(32,30)
     │
     ▼
Embedding
(32,30,128)
     │
     ▼
GRU
(32,30,64)
     │
     ▼
Final Hidden State
(32,64)
     │
     ▼
Linear
(32,1)
     │
     ▼
Sigmoid
(32,1)
     │
     ▼
Spam Probability
```

Suppose we use:

```python
batch_size = 32
sequence_length = 30
embedding_dim = 128
hidden_dim = 64
```

The data flows through the model as follows:

| Component             | Shape           |
| --------------------- | --------------- |
| Input token IDs       | `(32, 30)`      |
| Embedding             | `(32, 30, 128)` |
| GRU output            | `(32, 30, 64)`  |
| Final hidden state    | `(32, 64)`      |
| Fully connected layer | `(32, 1)`       |
| Sigmoid output        | `(32, 1)`       |

The important point is that the GRU converts a sequence of 30 token IDs into a single 64-dimensional representation for each SMS message.

## 4. Training the GRU Model

After creating the GRU classifier, the next step is to train the model using the training dataset.

The training procedure is essentially the same as the training procedures used for the FFNN, RNN, and LSTM models.


### 4.1 Defining the Loss Function and Optimizer

Since the GRU classifier contains a Sigmoid activation function at its output, the model produces a probability between 0 and 1.

Therefore, we use **Binary Cross-Entropy Loss (`BCELoss`)**.

```python
import torch.optim as optim

criterion = nn.BCELoss()

optimizer = optim.Adam(
    model_GRU.parameters(),
    lr=0.001
)
```

The `BCELoss` function compares the predicted probability with the true class label.

The Adam optimizer then updates the trainable parameters using the gradients calculated during backpropagation.

### 4.2 Training Loop

In **Section 13. NLP: Feed-Forward Neural Networks for Text Classification**, we implemented the `train_model()` function to train the neural network, calculate training and test metrics, and store the loss and accuracy values for each epoch.

Since the training procedure is independent of the specific recurrent architecture, the same function can be reused for the GRU model.

We therefore pass the GRU model to the previously implemented `train_model()` function:

```python
train_losses_GRU, test_losses_GRU, \
train_accuracies_GRU, test_accuracies_GRU = train_model(
    model=model_GRU,
    train_loader=train_loader,
    test_loader=test_loader,
    epochs=10
)
```

This process is repeated for all mini-batches and for the specified number of epochs.

A typical training result may look like:

```text
Epoch [1/10] Train Loss: 0.1652 Train Accuracy: 0.9465 Test Loss: 0.0954 Test Accuracy: 0.9722

Epoch [2/10] Train Loss: 0.0598 Train Accuracy: 0.9845 Test Loss: 0.0721 Test Accuracy: 0.9794

Epoch [3/10] Train Loss: 0.0312 Train Accuracy: 0.9924 Test Loss: 0.0705 Test Accuracy: 0.9812

...

Epoch [10/10] Train Loss: 0.0054 Train Accuracy: 0.9993 Test Loss: 0.0917 Test Accuracy: 0.9821
```

The training accuracy generally increases as the GRU learns patterns from the training SMS messages. The test accuracy indicates how well the model generalizes to unseen messages.

A large difference between training and test performance may indicate **overfitting**, while low performance on both datasets may indicate **underfitting**.

## 5. Visualizing GRU Training Performance

After training the GRU model, the stored loss and accuracy values can be visualized to analyze the learning behavior of the network.

In **Section 13. NLP: Feed-Forward Neural Networks for Text Classification**, we implemented the `plot_loss_accuracy()` function for visualizing training and test performance.

Since the training procedure for the GRU model follows the same workflow, the same function can be reused without modification.

```python
plot_loss_accuracy(
    epochs=10,
    train_losses=train_losses_GRU,
    test_losses=test_losses_GRU,
    train_accuracies=train_accuracies_GRU,
    test_accuracies=test_accuracies_GRU
)
```

The function generates two plots:

1. **Training and test loss curves**
2. **Training and test accuracy curves**

The loss curves show how the classification error changes during training.

Ideally, the training loss should decrease as the GRU learns useful patterns from the SMS messages.

The accuracy curves show how classification performance changes across epochs.

By comparing training and test performance, we can analyze the generalization ability of the model.

For example:

* A large difference between training and test accuracy may indicate **overfitting**.
* Low accuracy on both training and test datasets may indicate **underfitting**.
* Similar training and test performance generally indicates **better generalization**.

The plots can also help determine whether the model has already reached a stable performance level and whether additional training epochs are providing meaningful improvements.

## 6. Evaluating the GRU Model

After completing the training process, the final performance of the GRU classifier is measured using the unseen test dataset.

In **Section 13. NLP: Feed-Forward Neural Networks for Text Classification**, we implemented the `evaluate()` function to calculate the classification accuracy of a trained model.

The same function can be reused for the GRU model:

```python
evaluate(model_GRU)
```

A typical output may be:

```text
Test Accuracy: 0.9830
```

The test accuracy represents the proportion of SMS messages that were correctly classified by the trained GRU model.

For example:

```text
0.9830
```

means that approximately **98.30%** of the messages in the test dataset were classified correctly.
