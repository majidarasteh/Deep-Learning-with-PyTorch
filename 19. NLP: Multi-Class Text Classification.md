# NLP: Multi-Class Text Classification

In the previous sections, we developed neural network models for **binary text classification**, where each SMS message was assigned to one of two classes, such as:

```text
ham  → 0
spam → 1
```

However, many real-world NLP problems contain **more than two classes**.

For example, news articles may be classified into:

```text
sports
politics
technology
business
entertainment
```

This type of problem is called **multi-class classification**.

In this section, we extend our previous binary text classification framework to support multiple classes.

# 1. Multi-Class Classification

In multi-class classification, each input belongs to **exactly one class out of several possible classes**.

For example, suppose we have four classes:

```text
0 → sports
1 → politics
2 → technology
3 → business
```

Instead of producing one output, the model produces **one logit for each class**.

For four classes:

```text
Linear Layer
     ↓
4 logits
```

For example:

```text
[1.2, -0.5, 3.4, 0.8]
```

The largest value is:

```text
3.4
```

which corresponds to:

```text
Class 2 → technology
```

Therefore, the predicted class is obtained using:

```python
torch.argmax(outputs, dim=1)
```

# 2. Changes Required for Multi-Class Classification

The complete difference can be summarized as follows:

| Component            | Binary        | Multi-Class           |
| -------------------- | ------------- | --------------------- |
| Number of classes    | 2             | >2                    |
| Output neurons       | 1             | `num_classes`         |
| Activation in model  | Sigmoid       | None                  |
| Loss                 | `BCELoss()`   | `CrossEntropyLoss()`  |
| Prediction           | Threshold 0.5 | `argmax()`            |
| Probability function | Sigmoid       | Softmax               |
| Labels               | `0`, `1`      | `0 ... num_classes-1` |

For example, if we have five classes:

```python
num_classes = 5
```

the final layer becomes:

```python
nn.Linear(hidden_dim, num_classes)
```

and produces:

```text
[logit_0, logit_1, logit_2, logit_3, logit_4]
```

# 3. Preparing Multi-Class Labels

The labels should be represented as integer class IDs.

For example:

```text
sports      → 0
politics    → 1
technology  → 2
business    → 3
```

Therefore, a batch of labels may look like:

```python
tensor([0, 2, 1, 3, 2])
```

For `CrossEntropyLoss`, the labels should have:

```python
dtype=torch.long
```

For example:

```python
labels = labels.long()
```

Unlike binary classification, we do **not** convert the labels into probabilities or one-hot vectors when using `CrossEntropyLoss`.


# 4. Multi-Class Accuracy Function

This is one of the important changes from our binary classification implementation.

For binary classification, our accuracy function could use a threshold:

```python
predictions = (outputs >= 0.5).float()
```

This approach is not appropriate for multi-class classification.

Instead, we select the class with the largest logit.

We can define:

```python
def accuracy_fn(labels, outputs):

    predictions = torch.argmax(outputs, dim=1)

    accuracy = (predictions == labels).float().mean()

    return accuracy.item()
```

Here:

```python
torch.argmax(outputs, dim=1)
```

selects the class with the highest score for each sample.

For example:

```text
Outputs:

[1.2, 3.5, 0.7, -1.1]
```

The largest value is:

```text
3.5
```

which corresponds to:

```text
Class 1
```

Therefore:

```python
torch.argmax(outputs, dim=1)
```

returns:

```text
1
```

# 5. Building a Multi-Class Model

The architecture of the neural network can remain almost identical to the binary model.

The main change is the final layer.

Suppose we are using a Feed-Forward Neural Network:

```python
class FeedForwardClassifier(nn.Module):

    def __init__(
        self,
        vocab_size,
        embedding_dim,
        hidden_dim,
        num_classes
    ):

        super().__init__()

        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )

        self.classifier = nn.Sequential(

            nn.Linear(
                embedding_dim,
                hidden_dim
            ),

            nn.ReLU(),

            nn.Linear(
                hidden_dim,
                num_classes
            )
        )

    def forward(self, x):

        x = self.embedding(x)

        x = x.mean(dim=1)

        x = self.classifier(x)

        return x
```

Notice that we removed:

```python
nn.Sigmoid()
```

This is important because `CrossEntropyLoss` expects **raw logits**.


# 6. Understanding the Output

Suppose:

```python
num_classes = 4
```

and the batch size is:

```python
batch_size = 32
```

The model output will have the shape:

```text
(32, 4)
```

For example:

```text
Message 1 → [1.2, 3.5, 0.7, -1.1]
Message 2 → [4.1, 0.2, 1.5, 0.8]
Message 3 → [0.4, 0.9, 3.2, 1.1]
```

Each row corresponds to one input message.

Each column corresponds to one class:

```text
             Class 0   Class 1   Class 2   Class 3

Message 1      1.2       3.5       0.7      -1.1
Message 2      4.1       0.2       1.5       0.8
Message 3      0.4       0.9       3.2       1.1
```

The predicted classes are:

```text
Message 1 → Class 1
Message 2 → Class 0
Message 3 → Class 2
```

using:

```python
predictions = torch.argmax(outputs, dim=1)
```

# 7. Using CrossEntropyLoss

For multi-class classification, we replace:

```python
criterion = nn.BCELoss()
```

with:

```python
criterion = nn.CrossEntropyLoss()
```

Therefore:

```python
criterion = nn.CrossEntropyLoss()

optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.001
)
```

An important difference is that `CrossEntropyLoss` internally handles the softmax operation.

Therefore, we should **not** write:

```python
nn.Softmax()
```

inside the model before `CrossEntropyLoss`.

The model should return:

```text
raw logits
```

and `CrossEntropyLoss` handles the conversion internally.

# 8. Multi-Class Training Function

Now we can modify the training function from our binary classification tutorial.

The structure of the function remains almost identical. The main changes are:

1. Move inputs and labels to the selected device.
2. Use `CrossEntropyLoss`.
3. Use the multi-class `accuracy_fn`.
4. Do not use `Sigmoid`.
5. Do not apply a binary threshold.

```python
def train_model(
    model,
    train_loader,
    test_loader,
    criterion,
    optimizer,
    epochs=10
):

    # Store training history
    train_losses = []
    test_losses = []

    train_accuracies = []
    test_accuracies = []

    for epoch in range(epochs):

        # -----------------------
        # Training phase
        # -----------------------

        model.train()

        running_loss = 0.0
        running_accuracy = 0.0

        for inputs, labels in train_loader:

            # Move data to device
            inputs = inputs.to(device)
            labels = labels.to(device)

            # Clear gradients
            optimizer.zero_grad()

            # Forward pass
            outputs = model(inputs)

            # Calculate loss
            loss = criterion(outputs, labels)

            # Calculate accuracy
            accuracy = accuracy_fn(
                labels,
                outputs
            )

            # Backpropagation
            loss.backward()

            # Update parameters
            optimizer.step()

            running_loss += loss.item()
            running_accuracy += accuracy

        # Average training metrics
        epoch_train_loss = (
            running_loss / len(train_loader)
        )

        epoch_train_accuracy = (
            running_accuracy / len(train_loader)
        )

        # -----------------------
        # Evaluation phase
        # -----------------------

        model.eval()

        running_test_loss = 0.0
        running_test_accuracy = 0.0

        with torch.no_grad():

            for inputs, labels in test_loader:

                # Move data to device
                inputs = inputs.to(device)
                labels = labels.to(device)

                # Forward pass
                outputs = model(inputs)

                # Calculate loss
                loss = criterion(
                    outputs,
                    labels
                )

                # Calculate accuracy
                accuracy = accuracy_fn(
                    labels,
                    outputs
                )

                running_test_loss += loss.item()
                running_test_accuracy += accuracy

        # Average test metrics
        epoch_test_loss = (
            running_test_loss / len(test_loader)
        )

        epoch_test_accuracy = (
            running_test_accuracy / len(test_loader)
        )

        # Store metrics
        train_losses.append(epoch_train_loss)
        test_losses.append(epoch_test_loss)

        train_accuracies.append(
            epoch_train_accuracy
        )

        test_accuracies.append(
            epoch_test_accuracy
        )

        # Display results
        print(
            f"Epoch [{epoch + 1}/{epochs}] "
            f"Train Loss: {epoch_train_loss:.4f} "
            f"Train Accuracy: {epoch_train_accuracy:.4f} "
            f"Test Loss: {epoch_test_loss:.4f} "
            f"Test Accuracy: {epoch_test_accuracy:.4f}"
        )

    return (
        train_losses,
        test_losses,
        train_accuracies,
        test_accuracies
    )
```

# 12. Multi-Class Prediction Function

The prediction function also needs to be changed from binary classification.

For binary classification, we used something similar to:

```python
probability >= 0.5
```

For multi-class classification, we instead select the class with the largest output value.

We can write:

```python
def predict(text, model):

    model.eval()

    # Convert text to token IDs
    tokens = tokenize(text)

    # Convert tokens to tensor
    input_tensor = torch.tensor(
        tokens,
        dtype=torch.long
    ).unsqueeze(0)

    # Move input to device
    input_tensor = input_tensor.to(device)

    with torch.no_grad():

        # Get model outputs
        outputs = model(input_tensor)

        # Get predicted class
        prediction = torch.argmax(
            outputs,
            dim=1
        )

    return prediction.item()
```

The important line is:

```python
prediction = torch.argmax(outputs, dim=1)
```

For example, suppose the model produces:

```text
[1.2, 0.4, 3.8, 0.7]
```

Then:

```python
torch.argmax(outputs, dim=1)
```

returns:

```text
2
```

Therefore, the predicted class is:

```text
Class 2
```


# 13. Multi-Class Prediction with Class Names

It is more useful to return the actual class name rather than only the class ID.

Suppose we have:

```python
class_names = [
    "sports",
    "politics",
    "technology",
    "business"
]
```

We can modify the prediction function:

```python
def predict(text, model, class_names):

    model.eval()

    # Convert text to token IDs
    tokens = tokenize(text)

    # Convert to tensor
    input_tensor = torch.tensor(
        tokens,
        dtype=torch.long
    ).unsqueeze(0)

    # Move to device
    input_tensor = input_tensor.to(device)

    with torch.no_grad():

        outputs = model(input_tensor)

        prediction = torch.argmax(
            outputs,
            dim=1
        )

    predicted_class = prediction.item()

    return class_names[predicted_class]
```

Then:

```python
text = "The football team won the match."

prediction = predict(
    text,
    model,
    class_names
)

print("Prediction:", prediction)
```

Possible output:

```text
Prediction: sports
```

# 14. Obtaining Class Probabilities

Sometimes we also want to know the probability associated with each class.

Although `CrossEntropyLoss` requires raw logits during training, we can apply `softmax` during prediction:

```python
probabilities = torch.softmax(
    outputs,
    dim=1
)
```

For example, the model may produce:

```text
Sports       → 0.82
Politics     → 0.05
Technology   → 0.08
Business     → 0.05
```

The predicted class is:

```text
Sports
```

because it has the highest probability.

We can therefore write:

```python
def predict(text, model, class_names):

    model.eval()

    tokens = tokenize(text)

    input_tensor = torch.tensor(
        tokens,
        dtype=torch.long
    ).unsqueeze(0)

    input_tensor = input_tensor.to(device)

    with torch.no_grad():

        outputs = model(input_tensor)

        probabilities = torch.softmax(
            outputs,
            dim=1
        )

        prediction = torch.argmax(
            probabilities,
            dim=1
        )

    predicted_class = prediction.item()

    predicted_probability = probabilities[
        0,
        predicted_class
    ].item()

    return (
        class_names[predicted_class],
        predicted_probability
    )
```

We can then use:

```python
text = "The football team won the championship."

prediction, probability = predict(
    text,
    model,
    class_names
)

print("Message     :", text)
print("Probability :", f"{probability:.4f}")
print("Prediction  :", prediction)
```

Possible output:

```text
Message     : The football team won the championship.

Probability : 0.9417

Prediction  : sports
```

# 15. Using the Same Architecture for RNN, LSTM, GRU, and TextCNN

One useful point for your tutorial is that **multi-class classification does not require a completely new neural network architecture**.

For example, your previous GRU model may have had:

```python
self.fc = nn.Linear(
    hidden_dim,
    1
)
```

For multi-class classification, simply change it to:

```python
self.fc = nn.Linear(
    hidden_dim,
    num_classes
)
```

and remove:

```python
self.sigmoid = nn.Sigmoid()
```

The same idea applies to your LSTM:

```python
self.fc = nn.Linear(
    hidden_dim,
    num_classes
)
```

and your TextCNN:

```python
self.fc = nn.Linear(
    num_filters * len(filter_sizes),
    num_classes
)
```

The recurrent or convolutional feature extractor can remain unchanged.

The **classification head** changes from:

```text
features
   ↓
Linear
   ↓
1 output
   ↓
Sigmoid
```

to:

```text
features
   ↓
Linear
   ↓
num_classes outputs
```

with `CrossEntropyLoss` used during training.

This makes multi-class classification a natural extension of all the models you have already developed in the previous sections.
