# NLP: Multi-Class Text Classification

In the previous sections, we developed neural network models for **binary text classification**, where each SMS message was assigned to one of two classes, such as:

```text
ham  → 0
spam → 1
```

However, many real-world NLP problems contain **more than two classes**.

For example, news text may be classified into:

```text
Household
Books
Clothing & Accessories
Electronics
```

This type of problem is called **multi-class classification**.

In this section, we extend our previous binary text classification framework to support multiple classes.

# 1. Multi-Class Classification

In multi-class classification, each input belongs to **exactly one class out of several possible classes**.

For example, suppose we have four classes:

```text
0 → Household
1 → Books
2 → Clothing & Accessories
3 → Electronics
```

Instead of producing one output, the model produces **one logit for each class**.

For four classes:

```text
Linear Layer
     ↓
4 logits
```

For example:

```text
[1.2, -0.5, 3.4, 0.8]
```

The largest value is:

```text
3.4
```

which corresponds to:

```text
Class 2 → Clothing & Accessories
```

Therefore, the predicted class is obtained using:

```python
torch.argmax(outputs, dim=1)
```

# 2. Changes Required for Multi-Class Classification

The complete difference can be summarized as follows:

| Component            | Binary        | Multi-Class           |
| -------------------- | ------------- | --------------------- |
| Number of classes    | 2             | >2                    |
| Output neurons       | 1             | `num_classes`         |
| Activation in model  | Sigmoid       | None                  |
| Loss                 | `BCELoss()`   | `CrossEntropyLoss()`  |
| Prediction           | Threshold 0.5 | `argmax()`            |
| Probability function | Sigmoid       | Softmax               |
| Labels               | `0`, `1`      | `0 ... num_classes-1` |

For example, if we have five classes:

```python
num_classes = 4
```

the final layer becomes:

```python
nn.Linear(hidden_dim, num_classes)
```

and produces:

```text
[logit_0, logit_1, logit_2, logit_3]
```

# 3. Preparing Multi-Class Labels

The labels should be represented as integer class IDs.

For example:

```text
0 → Household
1 → Books
2 → Clothing & Accessories
3 → Electronics
```

Therefore, a batch of labels may look like:

```python
tensor([0, 2, 1, 3, 2])
```

For `CrossEntropyLoss`, the labels should have:

```python
dtype=torch.long
```

For example:

```python
labels = labels.long()
```

Unlike binary classification, we do **not** convert the labels into probabilities or one-hot vectors when using `CrossEntropyLoss`.

Therefore, the `SMSDataset` class introduced in **Section 13** should be modified slightly for multi-class classification. Since we use `CrossEntropyLoss()` instead of `BCELoss()`, the class labels must be stored as integer values using `dtype=torch.long`. The modified `SMSDataset` class is as follows:

```python
class SMSDataset(Dataset):

    def __init__(self, dataframe):

        self.texts = dataframe["text"].tolist()
        self.labels = dataframe["label"].tolist()

    def __len__(self):
        return len(self.texts)

    def __getitem__(self, idx):

        x = vectorize(self.texts[idx])

        y = torch.tensor(
            self.labels[idx],
            dtype=torch.long
        )

        return x, y
```

# 4. Multi-Class Accuracy Function

This is one of the important changes from our binary classification implementation.

For binary classification, our accuracy function could use a threshold:

```python
predictions = (outputs >= 0.5).float()
```

This approach is not appropriate for multi-class classification.

Instead, we select the class with the largest logit.

We can define:

```python
def accuracy_fn(labels, outputs):
    predictions = torch.argmax(outputs, dim=1)
    accuracy = (predictions == labels).float().mean()
    return accuracy.item()
```

Here:

```python
torch.argmax(outputs, dim=1)
```

selects the class with the highest score for each sample.

For example:

```text
Outputs:

[1.2, 3.5, 0.7, -1.1]
```

The largest value is:

```text
3.5
```

which corresponds to:

```text
Class 1
```

Therefore:

```python
torch.argmax(outputs, dim=1)
```

returns:

```text
1
```

# 5. Building a Multi-Class Model

The architecture of the neural network can remain almost identical to the binary model.

The main change is the final layer.

Suppose we are using a Feed-Forward Neural Network:

```python
class FeedForwardClassifier(nn.Module):

    def __init__(
        self,
        vocab_size,
        embedding_dim,
        hidden_dim,
        num_classes
    ):

        super().__init__()

        self.embedding = nn.Embedding(
            num_embeddings=vocab_size,
            embedding_dim=embedding_dim,
            padding_idx=0
        )

        self.classifier = nn.Sequential(

            nn.Linear(
                embedding_dim,
                hidden_dim
            ),

            nn.ReLU(),

            nn.Linear(
                hidden_dim,
                num_classes
            )
        )

    def forward(self, x):

        x = self.embedding(x)

        x = x.mean(dim=1)

        x = self.classifier(x)

        return x
```

Notice that we removed:

```python
nn.Sigmoid()
```

This is important because `CrossEntropyLoss` expects **raw logits**.

Now, suppose our dataset contains four classes:

```python
num_classes = 4
```

We can create the model as follows:

```python
device = torch.device("cuda" if torch.cuda.is_available() else "cpu")
print(device)

vocab_size = len(vocab)
embedding_dim = 128
hidden_dim = 64
num_classes = 4

model = FeedForwardClassifier(
    vocab_size=vocab_size,
    embedding_dim=embedding_dim,
    hidden_dim=hidden_dim,
    num_classes=num_classes
)
```

# 6. Understanding the Output

Suppose:

```python
num_classes = 4
```

and the batch size is:

```python
batch_size = 32
```

The model output will have the shape:

```text
(32, 4)
```

For example:

```text
Message 1 → [1.2, 3.5, 0.7, -1.1]
Message 2 → [4.1, 0.2, 1.5, 0.8]
Message 3 → [0.4, 0.9, 3.2, 1.1]
```

Each row corresponds to one input message.

Each column corresponds to one class:

```text
             Class 0   Class 1   Class 2   Class 3

Message 1      1.2       3.5       0.7      -1.1
Message 2      4.1       0.2       1.5       0.8
Message 3      0.4       0.9       3.2       1.1
```

The predicted classes are:

```text
Message 1 → Class 1
Message 2 → Class 0
Message 3 → Class 2
```

using:

```python
predictions = torch.argmax(outputs, dim=1)
```

# 7. Using CrossEntropyLoss

For multi-class classification, we replace:

```python
criterion = nn.BCELoss()
```

with:

```python
criterion = nn.CrossEntropyLoss()
```

Therefore:

```python
criterion = nn.CrossEntropyLoss()
optimizer = torch.optim.Adam(
    model.parameters(),
    lr=0.0001
)
```

An important difference is that `CrossEntropyLoss` internally handles the softmax operation.

Therefore, we should **not** write:

```python
nn.Softmax()
```

inside the model before `CrossEntropyLoss`.

The model should return:

```text
raw logits
```

and `CrossEntropyLoss` handles the conversion internally.

# 8. Multi-Class Training Function

Yes. The **training procedure remains essentially unchanged** from Section 13. The same `train_model()` function can be reused for multi-class classification because `CrossEntropyLoss()` and the updated `accuracy_fn()` already handle the multi-class outputs.

for multi-class classification, `squeeze()` is unnecessary and should preferably be removed. The model output has the shape `(batch_size, num_classes)`, which is exactly what `CrossEntropyLoss()` expects.

Therefore, the training function can remain as follows:

```python
def train_model(model, train_loader, test_loader, epochs=10):

    # Move model to device
    model = model.to(device)

    # Store the training history
    train_losses = []
    test_losses = []

    train_accuracies = []
    test_accuracies = []

    num_epochs = epochs

    for epoch in range(num_epochs):

        # -----------------------
        # Training phase
        # -----------------------
        model.train()

        running_loss = 0.0
        running_accuracy = 0.0

        for inputs, labels in train_loader:

            # Move data to device
            inputs = inputs.to(device)
            labels = labels.to(device)

            optimizer.zero_grad()

            # Forward pass
            outputs = model(inputs)

            # Compute loss
            loss = criterion(outputs, labels)

            # Compute accuracy
            accuracy = accuracy_fn(labels, outputs)

            # Backpropagation
            loss.backward()

            # Update model parameters
            optimizer.step()

            running_loss += loss.item()
            running_accuracy += accuracy

        # Average training metrics
        epoch_train_loss = running_loss / len(train_loader)
        epoch_train_accuracy = running_accuracy / len(train_loader)


        # -----------------------
        # Evaluation phase
        # -----------------------
        model.eval()

        test_loss = 0.0
        test_accuracy = 0.0

        with torch.no_grad():

            for inputs, labels in test_loader:

                # Move data to device
                inputs = inputs.to(device)
                labels = labels.to(device)

                outputs = model(inputs)

                # Compute loss
                loss = criterion(outputs, labels)

                # Compute accuracy
                accuracy = accuracy_fn(labels, outputs)

                test_loss += loss.item()
                test_accuracy += accuracy

        # Average test metrics
        epoch_test_loss = test_loss / len(test_loader)
        epoch_test_accuracy = test_accuracy / len(test_loader)


        # -----------------------
        # Store metrics
        # -----------------------
        train_losses.append(epoch_train_loss)
        test_losses.append(epoch_test_loss)

        train_accuracies.append(epoch_train_accuracy)
        test_accuracies.append(epoch_test_accuracy)


        print(
            f"Epoch [{epoch+1}/{num_epochs}] "
            f"Train Loss: {epoch_train_loss:.4f} "
            f"Train Accuracy: {epoch_train_accuracy:.4f} "
            f"Test Loss: {epoch_test_loss:.4f} "
            f"Test Accuracy: {epoch_test_accuracy:.4f}"
        )


    return (
        train_losses,
        test_losses,
        train_accuracies,
        test_accuracies
    )
```

Then, the model can be trained exactly as before:

```python
train_losses_FFNN, test_losses_FFNN, \
train_accuracies_FFNN, test_accuracies_FFNN = train_model(
    model=model_FFNN,
    train_loader=train_loader,
    test_loader=test_loader,
    epochs=10
)
```

The key point is that **the training loop itself does not need to know whether the problem is binary or multi-class**. The main changes were made in the **model output layer, loss function, label type, and accuracy calculation**.

A possible output could be:

```text

Epoch [2/10] Train Loss: 0.4312 Train Accuracy: 0.8563 Test Loss: 0.3821 Test Accuracy: 0.8734

Epoch [3/10] Train Loss: 0.2514 Train Accuracy: 0.9215 Test Loss: 0.2987 Test Accuracy: 0.9021

...

Epoch [10/10] Train Loss: 0.0421 Train Accuracy: 0.9882 Test Loss: 0.1874 Test Accuracy: 0.9415
```

The exact values depend on the dataset, preprocessing, model architecture, and hyperparameters.

# 9. Evaluating the Multi-Class Classification Model

After training the Feed-Forward Neural Network, we can evaluate its performance on the unseen test dataset. The `evaluate()` function introduced in Section 13 can be reused for the multi-class classification task because the `accuracy_fn()` function already uses `torch.argmax()` to select the class with the highest predicted score.

The model is first switched to evaluation mode using `model.eval()`. Then, `torch.no_grad()` is used to disable gradient computation because the model parameters are not updated during evaluation. For each batch, the inputs and labels are moved to the selected device, the model generates predictions, and the classification accuracy is calculated using `accuracy_fn()`.

The `evaluate()` function is implemented as follows:

```python
def evaluate(model):

    model.eval()
    total_accuracy = 0

    with torch.no_grad():
        for inputs, labels in test_loader:

            inputs = inputs.to(device)
            labels = labels.to(device)

            outputs = model(inputs).squeeze()
            accuracy = accuracy_fn(labels, outputs)
            total_accuracy += accuracy

    test_accuracy = total_accuracy / len(test_loader)
    print(f"Test Accuracy: {test_accuracy:.4f}")
```

We can evaluate the trained Feed-Forward Neural Network by calling:

```python
evaluate(model_FFNN)
```

For example, the output may be:

```text
Test Accuracy: 0.9345
```

Here, an accuracy of `0.9345` means that approximately **93.45% of the test samples were classified correctly** across the four classes.


# 10. Predicting the Class of New Text

After training and evaluating the multi-class classification model, we can use it to classify new text samples that were not included in the training or testing datasets.

Unlike binary classification, where the model produces a single probability using a Sigmoid activation function, the multi-class model produces **one output score for each class**. In our example, there are four classes:

```text
0 → Household
1 → Books
2 → Electronics
3 → Clothing & Accessories
```

The `predict()` function first tokenizes and vectorizes the input text. The resulting tensor is then reshaped to include a batch dimension and moved to the same device as the model. The model generates four output scores, and `torch.argmax()` selects the class with the highest score.

The prediction function is implemented as follows:

```python
def predict(text, model):

    class_names = [
        "Household",
        "Books",
        "Electronics",
        "Clothing & Accessories"
    ]

    model.eval()

    # Vectorize the text, add a batch dimension,
    # and move it to the same device as the model
    input_tensor = vectorize(text).unsqueeze(0).to(device)

    with torch.no_grad():

        # Generate class scores
        outputs = model(input_tensor)

        # Select the class with the highest score
        prediction = torch.argmax(outputs, dim=1).item()

    return class_names[prediction]
```

We can then provide a new product description to the model:

```python
text = "iPhone 17. Center Stage front camera. Latest-generation Ceramic Shield. 6.3-inch ProMotion display. A19 chip. Five gorgeous colors."

prediction = predict(text, model_FFNN)

print("Text:", text)
print("Prediction:", prediction)
```

A possible output is:

```text
Text: iPhone 17. Center Stage front camera. Latest-generation Ceramic Shield. 6.3-inch ProMotion display. A19 chip. Five gorgeous colors.
Prediction: Electronics
```

For example, the model may produce:

```text
Household                → 0.05
Books                    → 0.05
Clothing & Accessories   → 0.08
Electronics              → 0.82
```

The predicted class is:

```text
Electronics
```

because it has the highest probability.


# 11. Using the Same Architecture for RNN, LSTM, GRU, and TextCNN

One useful point for your tutorial is that **multi-class classification does not require a completely new neural network architecture**.

For example, your previous GRU model may have had:

```python
self.fc = nn.Linear(
    hidden_dim,
    1
)
```

For multi-class classification, simply change it to:

```python
self.fc = nn.Linear(
    hidden_dim,
    num_classes
)
```

and remove:

```python
self.sigmoid = nn.Sigmoid()
```

The same idea applies to your LSTM:

```python
self.fc = nn.Linear(
    hidden_dim,
    num_classes
)
```

and your TextCNN:

```python
self.fc = nn.Linear(
    num_filters * len(filter_sizes),
    num_classes
)
```


This makes multi-class classification a natural extension of all the models you have already developed in the previous sections.
