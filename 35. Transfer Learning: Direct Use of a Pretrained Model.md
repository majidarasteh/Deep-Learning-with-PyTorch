# Direct Use of a Pretrained Model with PyTorch

## 1. Introduction

In the **direct-use approach**, we use a pretrained model exactly as it was trained. We do not replace its classification layer, freeze or unfreeze selected layers, or train the model on a new dataset.

The pretrained model is already capable of performing its original task.

For example, a model trained on the ImageNet dataset can classify an input image into one of the categories it learned during training. ImageNet contains many different categories, including animals, vehicles, objects, food, and other everyday objects.

Therefore, if our goal is simply to identify the object in an image using one of the categories supported by the pretrained model, we can use the model directly.

The general process is:

1. Load the pretrained model and its pretrained weights.
2. Obtain the preprocessing transformations associated with those weights.
3. Load and preprocess an image.
4. Pass the image through the model and predicted the class index

No training is required.

## 2. Loading a Pretrained Model

PyTorch provides many pretrained image-classification models through `torchvision.models`.
For this tutorial, we use **ResNet50** with its pretrained ImageNet weights.

```python
import torch
from torchvision.models import resnet50, ResNet50_Weights

# Select pretrained weights
weights = ResNet50_Weights.DEFAULT

# Load the pretrained ResNet50 model
model = resnet50(weights=weights)

# Set the model to evaluation mode
model.eval()
```

The following line:

```python
model = resnet50(weights=weights)
```

loads the ResNet50 architecture together with pretrained parameters. The model has already learned to classify images into the categories associated with the selected pretrained weights.

Because we are not training the model, we use:

```python
model.eval()
```

This puts the model into evaluation mode. This is important because some neural-network layers, such as dropout and batch normalization, behave differently during training and evaluation.


## 3. Selecting the Computing Device

As with other PyTorch models, we can use either a GPU or CPU.

```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = model.to(device)
print(f"Using device: {device}")
```

If a CUDA-compatible GPU is available, the model is moved to the GPU. Otherwise, it runs on the CPU.

The input image must also be moved to the same device as the model.

## 4. Understanding the Pretrained Model's Classes

A pretrained classification model produces a numerical output for every class that it knows.

For example, the ImageNet-trained ResNet50 model produces **1,000 output scores**, corresponding to its 1,000 supported classes.
We can obtain the class names from the selected weights:

```python
categories = weights.meta["categories"]
print(f"Number of classes: {len(categories)}")
```

For example, we can inspect the first few categories:

```python
print(categories[:10])
```

The output will contain class names such as:

```text
tench
goldfish
great white shark
tiger shark
hammerhead
electric ray
stingray
cock
hen
ostrich
```

The exact list is provided by the metadata associated with the pretrained weights.

The important point is that the model returns numerical scores corresponding to all supported categories.

## 5. Using the Correct Image Preprocessing

A pretrained model expects its input to have a particular format.

The image preprocessing used during inference should be compatible with the preprocessing used when the pretrained weights were created.

Fortunately, `torchvision` provides the required preprocessing transformations through:

```python
weights.transforms()
```

We can create the preprocessing pipeline as follows:

```python
preprocess = weights.transforms()
```

We can inspect it:

```python
print(preprocess)
```

The transformation pipeline generally includes operations such as:

* resizing the image,
* cropping the image,
* converting the image to a tensor,
* scaling pixel values,
* normalizing the image.

The exact preprocessing depends on the selected pretrained weights.

Therefore, instead of manually guessing the required image size and normalization values, it is recommended to use:

```python
preprocess = weights.transforms()
```

## 6. Loading an Image

We can use the `PIL` library to open an image.

```python
from PIL import Image
image_path = "C:/Users/Majid/data/predict/image.jpg"
image = Image.open(image_path).convert("RGB")
print(image.size)
```

The `.convert("RGB")` operation ensures that the image has three color channels.

This is useful because pretrained ImageNet models generally expect RGB images.


## 7. Preprocessing the Image

Now we apply the preprocessing pipeline provided by the pretrained weights.

```python
input_tensor = preprocess(image)
```

The resulting tensor represents the image in the format expected by the model.

However, the model expects a **batch of images**, even if we are predicting only one image.

Therefore, we add a batch dimension:

```python
input_batch = input_tensor.unsqueeze(0)
```

The shape changes from:

```text
(C, H, W)
```

to:

```text
(1, C, H, W)
```

For example:

```text
3 × 224 × 224
```

becomes:

```text
1 × 3 × 224 × 224
```

where:

* `1` = number of images in the batch
* `3` = RGB channels
* `224 × 224` = image height and width

The exact input size is determined by the preprocessing associated with the selected weights.

## 8. Moving the Input to the Device

The input tensor must be on the same device as the model.

```python
input_batch = input_batch.to(device)
```

For example, if the model is running on a GPU:

```text
Model → GPU
Input → GPU
```

If the model is running on a CPU:

```text
Model → CPU
Input → CPU
```

## 9. Making a Prediction

We can now pass the image through the pretrained model.

Because we are only performing inference, we do not need to calculate gradients.

We can therefore use:

```python
with torch.no_grad():
    output = model(input_batch)
```

The output contains one score for each class.

For ResNet50 with ImageNet weights, the output shape is:

```python
print(output.shape)
```

which will be:

```text
torch.Size([1, 1000])
```

The first dimension represents the batch size, and the second dimension represents the number of classes.


## 10. Understanding the Model Output

The values returned by the model are called **logits**.

They are raw scores and are not probabilities.

For example, the output might conceptually look like:

```text
[-2.1, -1.3, 8.7, 0.4, ...]
```

The class with the highest score is the model's most likely prediction.

We can find the index of the class with the largest score using:

```python
predicted_class_index = output.argmax(dim=1).item()
```

Then we can obtain the corresponding class name:

```python
predicted_class = categories[predicted_class_index]
print(predicted_class)
```

For example, the model might produce:

```text
golden retriever
```

or:

```text
sports car
```

or:

```text
pizza
```

depending on the image.


## 11. Converting Logits to Probabilities

Although `argmax()` is enough to determine the most likely class, we may also want to know the model's confidence.

For a multi-class classification problem, we can convert logits into probabilities using the **softmax function**:

```python
probabilities = torch.softmax(output, dim=1)
```

The probabilities will sum approximately to 1:

```python
print(probabilities.sum())
```

For a single image, we can obtain the highest probability:

```python
predicted_probability = probabilities[0, predicted_class_index].item()
print(predicted_probability)
```

For example:

```text
0.87
```

This means the model assigned approximately 87% of its predicted probability to that class.

## 12. Complete Prediction Function

We can combine all the previous steps into a reusable function.

```python
def predict_image(model, image_path, weights, device):
    
    # Step 1: Get the preprocessing transformations
    preprocess = weights.transforms()
    
    # Step 2: Get the class names
    categories = weights.meta["categories"]
    
    # Step 3: Open the image
    image = Image.open(image_path).convert("RGB")
    
    # Step 4: Preprocess the image
    input_tensor = preprocess(image)
    
    # Step 5: Add batch dimension
    input_batch = input_tensor.unsqueeze(0).to(device)
    
    # Step 6: Set model to evaluation mode
    model.eval()
    
    # Step 7: Make prediction
    with torch.no_grad():
        output = model(input_batch)
        
    # Step 8: Convert logits to probabilities
    probabilities = torch.softmax(output, dim=1)
    
    # Step 9: Find the predicted class
    predicted_class_index = probabilities.argmax(dim=1).item()
    
    # Step 10: Get class name and probability
    predicted_class = categories[predicted_class_index]
    predicted_probability = probabilities[0, predicted_class_index].item()
    
    return predicted_class, predicted_probability
```

We can now use the function:

```python
image_path = "C:/Users/Majid/data/predict/image.jpg"

predicted_class, probability = predict_image(
    model=model,
    image_path=image_path,
    weights=weights,
    device=device
)

print(
    f"Prediction: {predicted_class} "
    f"(probability={probability:.4f})"
)
```

A possible output could be:

```text
Prediction: golden retriever (probability=0.8732)
```

The predicted category depends entirely on the input image.



## 13. Important Difference from Feature Extraction and Fine-Tuning

It is important to distinguish **direct use** from the other transfer-learning approaches.

| Approach           | Pretrained layers      | New classifier         | Training required |
| ------------------ | ---------------------- | ---------------------- | ----------------- |
| Direct use         | Used as they are       | No                     | No                |
| Feature extraction | Frozen                 | Usually added/replaced | Yes               |
| Fine-tuning        | Some/all are trainable | Usually added/replaced | Yes               |

In **direct use**, we do not modify the model.

For example:

```python
model = resnet50(weights=weights)
```

The model remains an ImageNet classifier.

In **feature extraction**, we would replace the final layer and train a new classifier:

```python
model.fc = nn.Linear(num_features, number_of_classes)
```

In **fine-tuning**, we would additionally allow some pretrained parameters to be updated.

Therefore, direct use is the simplest form of using a pretrained model.


## 14. When Should Direct Use Be Used?

Direct use is appropriate when the target problem is compatible with the task for which the pretrained model was created.

For example, if the pretrained model was trained to recognize a large collection of everyday objects and your application needs to recognize objects from those same categories, direct inference may be sufficient.

However, direct use is **not** appropriate when your target classes are different from the pretrained model's classes.

For example, suppose a pretrained ImageNet model recognizes:

```text
cat
dog
car
truck
airplane
...
```

but your application requires:

```text
healthy leaf
powdery mildew
rust disease
leaf spot
...
```

The original model does not have these target classes.
In this situation, simply using the pretrained model directly cannot solve the new classification problem. Instead, **feature extraction or fine-tuning** would usually be more appropriate.
