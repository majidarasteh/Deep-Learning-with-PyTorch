# Transfer Learning with PyTorch

## 1. Introduction to Transfer Learning

In deep learning, training a model from scratch usually requires a large dataset, considerable computational resources, and sufficient training time. However, in many real-world problems, collecting a large dataset and training a complex model from the beginning may not be practical.

Transfer learning is a machine learning technique in which knowledge learned by a model on one task is reused to help solve another, often related, task. Instead of initializing all model parameters randomly and learning everything from the beginning, we start with a model that has already learned useful patterns from existing data.

For example, consider a deep learning model trained to classify images of 1,000 different objects. During training, the model may learn general visual patterns such as edges, textures, shapes, and object parts. These learned representations can also be useful for a new task, such as classifying 10 types of animals. We can reuse the pretrained model and adapt it to the new classification task rather than training a new model from scratch.

The general process is:

1. Train or obtain a pretrained model on a source dataset.

2. Transfer learned parameters or representations.

3. Adapt the model to the target dataset and task, if necessary.

The central idea is that a model does not necessarily need to learn all patterns again. If the source and target tasks share useful characteristics, knowledge acquired from the source task can facilitate learning on the target task.

## 2. Knowledge Transfer and Heterogeneous Transfer Learning

Knowledge can be transferred from different sources, including pretrained neural networks, previously trained models, different datasets, and related tasks. The usefulness of transferred knowledge depends on how relevant the source knowledge is to the target problem.

For example, a model trained on a large collection of natural images may learn features that are useful for classifying other natural images. However, a model trained on medical scans or satellite imagery may learn representations that differ from those required for ordinary photographs.

When source and target domains, feature spaces, or tasks differ, knowledge transfer can become more challenging. This is related to heterogeneous transfer learning, in which the source and target may have different feature representations or data characteristics.

An important challenge is negative transfer. It occurs when transferred knowledge does not help the target task and may even reduce its performance compared with training without that knowledge. For example, a model trained on one type of image may learn patterns that are not useful for a substantially different image domain. Transferring those patterns without suitable adaptation can negatively affect learning.

Therefore, pretrained models should not automatically be assumed to improve every task. The similarity between source and target data, the model architecture, and the adaptation strategy should be considered. Evaluating the transferred model on a separate validation dataset helps determine whether transfer learning is beneficial.

## 3. Advantages of Transfer Learning

Transfer learning offers several advantages, particularly when the target dataset is relatively small or training a deep neural network from scratch is computationally expensive.

### 3.1. Reusing Previously Learned Knowledge

A pretrained model has already learned useful patterns from its source dataset. When the source and target tasks are sufficiently similar, these learned representations can be reused to support the new task. This can reduce the amount of training required and may improve performance compared with training from random initialization.

### 3.2. Adapting a Pretrained Model to a New Task

A pretrained model can be modified to address a task that differs from its original purpose. For example, suppose a pretrained model was developed to classify images into 100 animal categories, but a new application requires classifying only 10 animal categories. The model's learned visual representations can be reused, while its final classification layer is replaced with a new layer containing 10 output units.

This allows the model to retain useful features learned from the original dataset while learning the distinctions required by the target task.

Transfer learning does not guarantee higher accuracy. Its effectiveness depends on the relationship between the source and target tasks, the quality of the pretrained weights, and the way the model is adapted.

## 4. Main Approaches to Transfer Learning

There are three common approaches to using pretrained models: direct use, feature extraction, and fine-tuning. The appropriate approach depends on whether the original task already matches the target task and how much adaptation is required.

### 4.1. Direct Use of a Pretrained Model

In the direct-use approach, a pretrained model is used for inference without modifying its architecture or retraining its parameters. This approach is suitable when the target task matches the task for which the model was trained, including its output categories and expected input format.

For example, if a pretrained model classifies images into 1,000 ImageNet categories and the application also requires classification into those same categories, the model can be used directly.

```Python
import torch
from torchvision.models import resnet50, ResNet50_Weights

# Load a pretrained ResNet50 model
weights = ResNet50_Weights.DEFAULT
model = resnet50(weights=weights)

# Set the model to evaluation mode
model.eval()
```

The model can now be used to make predictions on appropriately preprocessed images. The preprocessing requirements associated with the selected weights must be followed.

### 4.2. Feature Extraction

In feature extraction, the pretrained model is used to extract useful representations from input data, while a new classifier is trained for the target task. The pretrained feature-extraction layers are usually frozen, meaning their parameters are not updated during training.

For example, a pretrained model may have been trained to classify 1,000 ImageNet categories. If the target task requires classification into 10 categories, we can remove or replace the original classification layer and attach a new classifier with 10 outputs. The earlier layers continue to extract visual features, while only the new classifier is trained.

The following example uses a pretrained ResNet18 model for a new image-classification task with 10 classes.


```Python
import torch
import torch.nn as nn
from torchvision.models import resnet18, ResNet18_Weights

# Load the pretrained model
weights = ResNet18_Weights.DEFAULT
model = resnet18(weights=weights)

# Freeze all pretrained parameters
for param in model.parameters():
    param.requires_grad = False

# Replace the final classification layer
num_features = model.fc.in_features
model.fc = nn.Linear(num_features, 10)

# Optimize only the new classifier
optimizer = torch.optim.Adam(
    model.fc.parameters(),
    lr=0.001
)
```

Only the new `model.fc` layer is trainable. This approach can reduce training time and computational requirements because the pretrained feature extractor is not updated.

### 4.3. Fine-Tuning

Fine-tuning also starts with a pretrained model, but some or all of its pretrained parameters are allowed to update during training on the target dataset.

Unlike feature extraction, where the pretrained layers remain frozen, fine-tuning adapts the pretrained representations to the target task. It can involve retraining only a few upper layers, several deeper layers, or the entire network.

For example, a pretrained ResNet18 model may be adapted to classify 10 categories. We replace the final classification layer and unfreeze selected deeper layers so that the model can learn features more specific to the target dataset.

The following code demonstrates fine-tuning the final ResNet18 block and the new classifier:


```Python
import torch
import torch.nn as nn
from torchvision.models import resnet18, ResNet18_Weights

# Load the pretrained model
weights = ResNet18_Weights.DEFAULT
model = resnet18(weights=weights)

# Freeze all parameters
for param in model.parameters():
    param.requires_grad = False

# Unfreeze the final residual block
for param in model.layer4.parameters():
    param.requires_grad = True

# Replace the final classification layer
num_features = model.fc.in_features
model.fc = nn.Linear(num_features, 10)

# Define optimizer for trainable parameters
optimizer = torch.optim.Adam(
    filter(lambda p: p.requires_grad, model.parameters()),
    lr=0.0001
)
```

A smaller learning rate is often used for fine-tuning pretrained layers to avoid making large updates that could damage useful previously learned representations. The learning rate and number of unfrozen layers should be selected based on validation performance.

## 5. Pretrained Image Classification Models in PyTorch

For image-processing tasks, two widely used convolutional neural network architectures are ResNet and EfficientNet. Both are available in PyTorch's `torchvision` library with pretrained weights.

### 5.1. ResNet

ResNet (Residual Network) is a deep neural network architecture that uses skip connections, also known as residual connections. These connections allow information to bypass some layers and help gradients flow through deep networks during training.

ResNet is available in several variants, including ResNet18, ResNet34, ResNet50, ResNet101, and ResNet152. The variants differ in depth, model complexity, and computational requirements.

### 5.2. EfficientNet

EfficientNet is a family of convolutional neural networks designed to balance model accuracy and computational efficiency. It uses a compound scaling strategy that scales network depth, width, and input resolution together.

Its variants include EfficientNet-B0 through EfficientNet-B7, as well as EfficientNetV2 models. Different variants provide different trade-offs in model size, computational cost, and performance.

Both architectures can be used for direct inference, feature extraction, and fine-tuning. The appropriate model depends on the target dataset, available hardware, inference requirements, and validation results.

## 6. Finding and Downloading Pretrained Models

PyTorch provides pretrained models through the `torchvision.models` module. Its official documentation includes model architectures, available pretrained weights, performance information, and the preprocessing transformations required for each weight set.

Official resources:

* [TorchVision — Models and Pre-trained Weights](https://docs.pytorch.org/vision/master/models.html) 

* [PyTorch Hub](https://pytorch.org/hub/) 

* [TorchVision — Stable Model Documentation](https://pytorch.org/vision/stable/models.html) 

For example, the following code downloads the pretrained ResNet50 weights automatically when they are not already cached locally:


```Python
import torch
from torchvision.models import resnet50, ResNet50_Weights

# Select pretrained weights
weights = ResNet50_Weights.DEFAULT

# Load the pretrained model
model = resnet50(weights=weights)

# Set the model to evaluation mode
model.eval()

# Get the required preprocessing transformations
preprocess = weights.transforms()
```

Similarly, an EfficientNet-B0 model can be loaded as follows:


```Python
from torchvision.models import efficientnet_b0, EfficientNet_B0_Weights

# Select pretrained weights
weights = EfficientNet_B0_Weights.DEFAULT

# Load the pretrained model
model = efficientnet_b0(weights=weights)

# Set the model to evaluation mode
model.eval()

# Get the required preprocessing transformations
preprocess = weights.transforms()
```

When pretrained weights are selected, PyTorch downloads them automatically if necessary and stores them in its cache. The `weights.transforms()` method provides the preprocessing pipeline associated with those weights. This is important because using an incorrect image size, normalization, or other preprocessing operation can reduce model performance.

Note: Pretrained weights may have licensing terms or restrictions. Check the relevant model and dataset licenses before using them in a project.

## 7. Saving and Reusing a Transfer-Learned Model

After feature extraction or fine-tuning, the adapted model can be saved and reused in future applications. Saving the model's learned parameters avoids repeating the training process, provided that the corresponding model architecture is recreated when loading the parameters.

In PyTorch, the recommended approach is to save the model's `state_dict`, which contains its learned parameters.

### 7.1. Saving the Model

For example, after training a ResNet18 model for a 10-class classification task:


```Python
# Save the trained model parameters
torch.save(
    model.state_dict(),
    "resnet18_transfer_learning.pth"
)
```

If training needs to be resumed later, it can also be useful to save the optimizer state and the current epoch:


```Python
torch.save(
    {
        "epoch": epoch,
        "model_state_dict": model.state_dict(),
        "optimizer_state_dict": optimizer.state_dict()
    },
    "resnet18_checkpoint.pth"
)
```

### 7.2. Loading the Saved Model

To reuse the saved model, first recreate the same architecture and target classification layer, then load the saved parameters.


```Python
import torch
import torch.nn as nn
from torchvision.models import resnet18

# Recreate the model architecture
model = resnet18(weights=None)

# Recreate the target classification layer
num_features = model.fc.in_features
model.fc = nn.Linear(num_features, 10)

# Load the saved parameters
state_dict = torch.load(
    "resnet18_transfer_learning.pth",
    map_location=device,
    weights_only=True
)

model.load_state_dict(state_dict)

# Move model to the selected device
model = model.to(device)

# Set the model to evaluation mode
model.eval()
```

The recreated architecture must match the architecture used when saving the weights, including the modified classification layer. For a saved checkpoint that also contains optimizer information, the checkpoint can be loaded and its individual entries used to restore the model and optimizer states.

Once loaded, the model can be used for inference without retraining.
