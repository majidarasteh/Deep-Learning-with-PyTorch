
# 1. Introduction to Time Series Forecasting

Time series forecasting is used to predict future values based on observations collected over time. Unlike ordinary machine learning datasets, the observations in a time series have a chronological order, and previous observations often contain useful information about future observations.

Time series forecasting has many real-world applications, including:

* predicting **Bitcoin and cryptocurrency prices**,
* forecasting stock prices,
* predicting electricity consumption,
* forecasting product sales,
* predicting weather conditions and temperatures,
* forecasting traffic volume,
* predicting energy demand.

For example, suppose we have the daily closing prices of Bitcoin:

```text
Day 1    → $95,000
Day 2    → $96,200
Day 3    → $94,800
Day 4    → $97,100
Day 5    → $98,000
...
```

A forecasting model uses historical observations to estimate one or more future observations.


# 2. Window and Horizon

The input and output of a deep learning time-series model are usually defined using two important concepts:

* **Window**
* **Horizon**

## Window

The **window**, also called the **lookback window**, specifies how many previous observations are used as the input to predict future values.

For example:

```python
window = 7
```

means that the model receives the previous **7 observations** as input.

If the data represents daily Bitcoin prices:

```text
Day 1
Day 2
Day 3
Day 4
Day 5
Day 6
Day 7
   ↓
Input Window
```

the model uses these seven days to make a prediction.

## Horizon

The **horizon** specifies how far into the future, or how many future observations, the model should predict.

For example:

```python
horizon = 1
```

means that the model predicts the next observation.


## Many-to-One Forecasting

Suppose:

```python
window = 7
horizon = 1
```

The model receives seven historical observations and predicts one future observation.

```text
Input Window                       Output

[x₁, x₂, x₃, x₄, x₅, x₆, x₇]  →  [x₈]
```

This is called **many-to-one forecasting**.

For example:

```text
Bitcoin Prices

[95000, 96200, 94800, 97100,
 98000, 97500, 98900]

             ↓

          99200
```

The seven previous prices are used to predict the next price.


## Many-to-Many Forecasting

Suppose:

```python
window = 7
horizon = 3
```

The model receives seven historical observations and predicts the next three observations.

```text
Input Window                              Output Horizon

[x₁, x₂, x₃, x₄, x₅, x₆, x₇]  →  [x₈, x₉, x₁₀]
```

This is commonly referred to as **multi-step** or **many-to-many forecasting**.

Therefore, a general time-series forecasting model can be represented as:

```text
Historical Observations
        │
        ▼
   Input Window
   [x₁, ..., xₜ]
        │
        ▼
 Deep Learning Model
        │
        ▼
 Prediction Horizon
[xₜ₊₁, ..., xₜ₊ₕ]
```

where:

* (W) represents the window size,
* (H) represents the forecasting horizon.

## 2.1 Creating Multiple Samples Using a Sliding Window

The window does not move only once. We can move it across the entire time series to generate multiple training examples.

Suppose we have the following sequence:

```text
x₁, x₂, x₃, x₄, x₅, x₆, x₇, x₈, x₉, x₁₀
```

With:

```python
window = 4
horizon = 1
```

we can create the following samples:

```text
Sample 1:
Input  → [x₁, x₂, x₃, x₄]
Target → [x₅]

Sample 2:
Input  → [x₂, x₃, x₄, x₅]
Target → [x₆]

Sample 3:
Input  → [x₃, x₄, x₅, x₆]
Target → [x₇]

Sample 4:
Input  → [x₄, x₅, x₆, x₇]
Target → [x₈]

Sample 5:
Input  → [x₅, x₆, x₇, x₈]
Target → [x₉]

Sample 6:
Input  → [x₆, x₇, x₈, x₉]
Target → [x₁₀]
```

The input window moves one time step forward after each sample. This process is called the **sliding window approach**.

Conceptually:

```text
Time ──────────────────────────────────────────────►

Sample 1: [──── Window ────] [Target]
Sample 2:   [──── Window ────] [Target]
Sample 3:     [──── Window ────] [Target]
Sample 4:       [──── Window ────] [Target]
```

Sliding windows transform a single long time series into many input-target pairs that can be used to train a deep learning model.


## 2.2 Number of Generated Samples

Suppose a time series contains (N) observations, and we use:

* window size (W),
* horizon (H).

If the sliding window moves one step at a time, the number of samples is:

$[
N - W - H + 1
]$

For example, suppose:

```python
N = 1000
window = 7
horizon = 3
```

Then:

$[
1000 - 7 - 3 + 1 = 991
]$

Therefore, the original time series produces **991 training samples**.


## 2.3 Choosing the Window Size and Horizon

Both the window size and horizon are important **hyperparameters**.

### Small Window

A small window:

```python
window = 7
```

has some advantages:

* less computational cost,
* fewer input features,
* faster training.

However, it may not contain enough historical information to capture longer patterns.

### Large Window

A larger window:

```python
window = 90
```

allows the model to examine a longer history and may capture longer dependencies.

However:

* training requires more memory,
* computation increases,
* irrelevant historical information may introduce noise.

Similarly, a larger horizon makes forecasting more difficult because the model must predict further into the future.

For example:

```text
Horizon = 1
```

means:

> Predict tomorrow.

while:

```text
Horizon = 30
```

means:

> Predict the next 30 observations.

Generally, prediction uncertainty increases as the forecasting horizon becomes longer.


# 3. Main Types of Time-Series Patterns

A time series may exhibit different patterns. The four common categories are:

1. **Trend**
2. **Seasonality**
3. **Cyclical patterns**
4. **Irregular or random patterns**

A real-world time series can contain more than one of these patterns simultaneously.

For example, sales data may have both an increasing long-term trend and yearly seasonal patterns.

## 3.1 Trend

A **trend** represents the long-term direction of a time series.

The trend may be:

* upward,
* downward,
* approximately constant.

For example, if the long-term value of an asset gradually increases:

```text
Price
  │                         ●
  │                     ●
  │                 ●
  │             ●
  │         ●
  │     ●
  └──────────────────────────── Time
```

the series has an **upward trend**.

Bitcoin prices may exhibit an upward trend during a particular period, although financial time series can also experience substantial volatility and sudden structural changes.

## 3.2 Seasonal Pattern

**Seasonality** refers to a pattern that repeats at a known and relatively fixed interval.

For example:

* hourly data with a daily cycle → seasonal period = **24**,
* daily data with weekly seasonality → seasonal period = **7**,
* daily data with yearly seasonality → seasonal period ≈ **365**,
* monthly data with yearly seasonality → seasonal period = **12**.

Therefore, for daily observations with a yearly repeating pattern:

```text
seasonal_period = 365
```

means that the pattern is expected to repeat approximately every 365 observations.

For example, electricity consumption may increase every summer and decrease every winter.

## 3.3 Cyclical Pattern

A **cyclical pattern** describes long-term rises and falls that occur over time but do not necessarily repeat at fixed or regular intervals.

For example, an economy may experience:

```text
Growth → Recession → Recovery → Growth
```

The duration of each cycle may be different.

This is the main difference between cyclicality and seasonality:

* **Seasonality:** relatively fixed and repeating interval.
* **Cyclical behavior:** repeated long-term movement with an irregular duration.

## 3.4 Irregular or Random Time Series

Some time series do not exhibit a clear trend, seasonal pattern, or cyclical structure.

Instead, their movements may appear largely random:

```text
Value
  │    ●       ●
  │ ●     ●
  │       ●       ●
  │   ●       ●
  │ ●             ●
  └────────────────── Time
```

Such series may be dominated by noise or unpredictable external factors.


# 4. Univariate and Multivariate Time Series

Time series can also be categorized according to the number of variables used by the model.

## 4.1 Univariate Time Series

A **univariate time series** uses only one variable.

For example, suppose we want to predict the future Bitcoin price using only its historical price:

```text
Price at t-3
Price at t-2
Price at t-1
Price at t
```

The input may be:

```text
[96200, 94800, 97100, 98000]
```

and the target is the future Bitcoin price.

The tensor structure is typically:

```text
(batch_size, window_size, 1)
```

The value `1` indicates that there is only one feature.


## 4.2 Multivariate Time Series

A **multivariate time series** uses multiple variables or features to make predictions.

For Bitcoin forecasting, possible features might include:

* historical price,
* trading volume,
* mining rewards or network-related variables,
* hash rate,
* other market indicators.

Each time step may therefore contain several features:

```text
Time       Price       Volume      Hash Rate
------------------------------------------------
Day 1      95000       1.2B        ...
Day 2      96200       1.5B        ...
Day 3      94800       1.1B        ...
```

The input tensor may have the shape:

```text
(batch_size, window_size, num_features)
```

For example:

```text
(32, 7, 3)
```

means:

* `32` sequences in the batch,
* `7` historical time steps,
* `3` features at each time step.

# 5. Creating Training and Test Sets

Creating training and test sets for time series is fundamentally different from many standard machine-learning tasks, such as image classification or NLP classification.

In an ordinary classification problem, samples are often shuffled before splitting:

```text
Shuffle
   ↓
Training Set + Test Set
```

However, randomly shuffling a time series can destroy its chronological structure and can introduce **data leakage**.

Suppose we have observations from:

```text
Time  ───────────────────────────────→

Past                              Future
────────────────────────────────────────
|                                  |
Training                       Testing
```

A common approach is to use the earlier observations for training and later observations for testing.

For an 80/20 split:

```text
First 80%                    Last 20%
──────────                   ────────
 Training                       Test
```

For example:

```text
Day 1 -------------------------------------------- Day 1000

|---------------- Training ----------------|------ Test ------|
              First 800 days                  Last 200 days
```

The fundamental principle is:

> A model should learn only from information that would have been available at the time the prediction is made.

This prevents the model from learning from future observations.


# 6. Time-Series Evaluation Metrics

Since time-series forecasting usually predicts continuous numerical values, it is commonly evaluated using regression metrics.

Let:

* ($y_i$) be the actual value,
* ($\hat{y}_i$) be the predicted value,
* ($N$) be the number of predictions.

## 6.1 Mean Absolute Error (MAE)

$[
MAE =
\frac{1}{N}
\sum_{i=1}^{N}
|y_i-\hat{y}_i|
]$

MAE calculates the average absolute difference between predictions and actual values.

## 6.2 Mean Squared Error (MSE)

$[
MSE =
\frac{1}{N}
\sum_{i=1}^{N}
(y_i-\hat{y}_i)^2
]$

Because the errors are squared, large prediction errors receive a larger penalty.


## 6.3 Root Mean Squared Error (RMSE)

$[
RMSE = \sqrt{MSE}
]$

RMSE is expressed in the same unit as the original target variable.

For example, if Bitcoin prices are measured in dollars, RMSE is also measured in dollars.

## 6.4 Mean Absolute Percentage Error (MAPE)

$[
MAPE =
\frac{100}{N}
\sum_{i=1}^{N}
\left|
\frac{y_i-\hat{y}_i}{y_i}
\right|
]$

MAPE expresses the average error as a percentage.

However, it has an important limitation: it becomes problematic when actual values are zero or close to zero.


## 6.5 Symmetric Mean Absolute Percentage Error (sMAPE)

A common form is:

$[
sMAPE =
\frac{100}{N}
\sum_{i=1}^{N}
\frac{2|y_i-\hat{y}_i|}
{|y_i|+|\hat{y}_i|}
]$

sMAPE attempts to provide a more symmetric percentage-based error measure, although different conventions for the formula exist.


## 6.6 Mean Absolute Scaled Error (MASE)

MASE compares the forecasting error with the error of a naive forecasting method.

Conceptually:

$[
MASE =
\frac{\text{Average absolute forecast error}}
{\text{Average absolute naive forecast error}}
]$

Interpretation:

* ($MASE < 1$): the model performs better than the naive baseline.
* ($MASE = 1$): the model performs approximately the same as the naive baseline.
* ($MASE > 1$): the naive baseline performs better.

This makes MASE particularly useful when comparing forecasting performance across different datasets or scales.

# 7. Uncertainty in Time-Series Forecasting

Forecasting is inherently associated with **uncertainty**.

Even with a well-trained model, the future cannot always be predicted exactly. The model's uncertainty can broadly be divided into two important categories.

## 7.1 Aleatoric Uncertainty

**Aleatoric uncertainty** represents uncertainty caused by inherent randomness or variability in the observed process.

Collecting additional training data generally cannot completely eliminate this type of uncertainty.

For example, suppose a train is scheduled to arrive at:

```text
09:00
```

Unexpected events such as:

* weather conditions,
* mechanical problems,
* passenger delays,
* temporary operational issues

may affect the actual arrival time.

Even with a large amount of historical data, some of this uncertainty remains inherently unpredictable.

## 7.2 Epistemic Uncertainty

**Epistemic uncertainty** results from insufficient knowledge about the underlying process.

Unlike aleatoric uncertainty, epistemic uncertainty can often be reduced by:

* collecting more relevant data,
* improving the model,
* adding useful features.

The **coconut tree example** is a useful intuitive illustration: if you do not know where coconuts are likely to fall, your uncertainty about being hit is high. By collecting more information about the environment or moving to a safer location, your uncertainty can be reduced.

The correct technical term is **epistemic uncertainty**.


# 8. The Turkey Problem in Time Series

The **Turkey Problem**, often associated with Nassim Nicholas Taleb's discussion of induction and the "Black Swan" problem, provides an important warning for forecasting.

Imagine a turkey that is fed every day.

Its historical data might look like:

```text
Day 1     → Fed
Day 2     → Fed
Day 3     → Fed
...
Day 1000  → Fed
```

Based only on historical observations, the turkey may infer:

> "I will continue to be fed tomorrow."

However, an exceptional event occurs:

```text
Thanksgiving → Turkey is killed
```

The historical pattern suddenly breaks.

The lesson for time-series forecasting is that:

> **A model can perform very well on historical patterns while completely failing when an unexpected structural change occurs.**

For example, Bitcoin may show a strong upward or downward pattern over a particular period. However, an unexpected event—such as a major regulatory action, market crisis, exchange failure, or geopolitical shock—can cause a sudden movement that historical patterns alone could not reliably predict.

This is closely related to concepts such as:

* distribution shift,
* regime change,
* structural breaks,
* black swan events.

It is an important limitation to discuss in a deep-learning time-series tutorial.


# 9. Models for Time Series Forecasting

Different models can be used depending on the dataset and forecasting problem.

## 9.1 Naive Baseline Model

The simplest forecasting model assumes that the next value will be equal to the most recent observed value:

$[\hat{y}(t) = y({t-1})]$

In Python, the basic idea is:

```python
prediction = previous_value
```

A naive baseline is extremely important because a complex deep-learning model should demonstrate that it performs better than a simple baseline.


## 9.2 Conv1D

A one-dimensional convolutional neural network can learn local temporal patterns.

```text
Input Time Series
       ↓
    Conv1D
       ↓
 Local Patterns
       ↓
Pooling / Conv1D
       ↓
Prediction
```

Conv1D is particularly useful for detecting local patterns within a fixed historical window.

## 9.3 RNN, GRU, and LSTM

Recurrent neural networks process observations sequentially and maintain information from previous time steps.

```text
x₁ → RNN → h₁
             ↓
x₂ → RNN → h₂
             ↓
x₃ → RNN → h₃
```

LSTM and GRU architectures were designed to handle long-term dependencies more effectively than a simple RNN.


## 9.4 N-BEATS

**N-BEATS** is a neural architecture designed specifically for time-series forecasting. It uses stacked fully connected blocks and residual connections rather than recurrent layers.

Conceptually:

```text
Input Window
      ↓
 N-BEATS Block
      ↓
 Backcast + Forecast
      ↓
 Residual
      ↓
 Additional Blocks
      ↓
 Final Forecast
```

It is a useful model to introduce after simpler architectures because it demonstrates that effective time-series models do not necessarily require RNNs or LSTMs.
